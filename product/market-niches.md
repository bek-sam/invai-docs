# Market niches (taxonomy for market signals)

- Owner: `product-manager`. Read-only for everyone else; the market-module card owner converts the JSON below into the module's data file mechanically.
- Used by: `specs/market-signals.md`, "Step 2: normalize", item 1 (design → niche mapping, canonical queries for outside demand, seasonality prior). Scope ref: `product/scope.md#market-signals` and `#market-and-digest-fences`.
- 69 niches in 8 families, keys exactly as in the spec's starter table (the spec's heading said 64; the table itself lists 69, and all 69 are kept).

## Fields
| Field | Meaning |
|---|---|
| `key` | Stable id (kebab-case). Never renamed once shipped; a retired niche keeps its key. |
| `family` | One of the 8 families in the spec table. |
| `labelEn`, `labelEs` | What the shop sees (chip on the design, assistant answers). Spanish is Mexican/US Spanish. |
| `queries` | 3–5 canonical US-English buyer phrases used to ask outside demand sources (mock until OI-9 and the approvals land). Generic phrases only. |
| `stems` | 4–10 lowercase ASCII stems matched against a design's tags and name tokens (English plus common Spanish tagging). Matching rule for the card owner: lowercase and strip accents from tags first ("maestría" → "maestria"); a stem matches a token that starts with it; stems of 3 characters or fewer (`mom`, `cat`, `rn`, `5k`) match the whole token only. |
| `peakMonths` | Months 1–12 when the niche is clearly seasonal (a holiday, a dated event or season). Empty when demand is year-round. It's a prior only: measured seasonality (spec Step 3) replaces it when data exists. |

## Trademark rule (clean by construction)
No label, query or stem names a team, league, school, brand, character, celebrity, film or TV title, military branch, or a registered slogan. Phrases that are common but known to be claimed as marks (for example certain "squad", "tribe", "thin line" and "game day" phrasings) are left out on purpose, and military niches use "military", "soldier" and "veteran", never branch names. State and city names are not stems; `local-pride` relies on the model fallback for them. The trademark screen (spec Step 2.3) still runs on every query and label before use; anything it drops is counted and fixed here.

## Adding or changing a niche
Anyone may propose one (task report or wave file) with evidence: at least two shops' catalogs or tickets showing designs that land in `unclassified` or in the wrong niche. The PM reviews it like copy (plain labels in both languages, this trademark rule, stems that don't collide with another niche's meaning), adds a changelog line below, and tells the market-module owner to regenerate the data file. Keys are never reused.

## Notes for reviewers
- `coach`: the key stays as the spec has it, but "coach" alone is also a fashion brand. Queries always say "sports coach" or pair it with team/gift wording; if the trademark screen still flags a query, drop that query, not the niche.
- `birthday-squad`: key kept; labels and the top queries say "group" and "crew", and "squad" stays only as a stem and one plain query ("birthday squad shirt"), which the trademark screen checks like the rest.
- Stems that overlap between niches are intended (for example `mom` in `mom`, `dog-mom`, `cat-mom`, `mothers-day`): the mapper keeps the two niches with the most matched stems (spec Step 2.2.1), so "dog mom" tags land on `dog-mom`.
- Known loose stems to watch in the first import dry run: `gato` (also starts "gator"), `trailer`, `cancer` (zodiac), `senior`, `mayo`. Customer-success checks the pilot catalog against this list (spec open question 1).
