Held back from backend-engineer(digest) until after the T-19-3 report lands, then added to
`invai-backend/src/modules/digest/digest.acceptance.test.ts` (or a new file in the same directory)
and run before review.

1. **Hour changed mid-week.** Build a digest for week N at hour 7. Before week N+1's sweep, call
   `digest.settings.set({hour: 9})`. Assert: week N's already-`ready` digest is untouched (no
   rebuild, no re-send), and week N+1 builds at 09:xx, not 07:xx. The spec doesn't say this
   explicitly (AC5 only covers "hour set once, before any build") — this proves the setting only
   ever governs the *next* build.

2. **Refund after the digest is built.** Build a digest whose glance net includes an order; then
   insert a `profitLines` row update (or a refund line) for that same order, as if
   `finance.recomputeProfit` ran later that day. Re-fetch `digest.get` for the same `weekKey`:
   assert the stored numbers are unchanged (spec: "out of scope, re-sending an email when late fees
   or refunds land" — the digest is a snapshot, not a live view). This guards against an
   accidental live JOIN in `digest.get` instead of a stored snapshot.

3. **Two recipients, staggered opt-in.** Person A opts in before the digest for week N exists;
   person B opts in the day after week N's digest is already `ready`. Assert: A gets exactly one
   email for week N, B gets none for week N (per AC23, "next week's" email only) and exactly one
   for week N+1. Tests the boundary between "opted in before build" and "opted in after build,
   before send" more precisely than AC23's single-person case.

4. **Role change mid-week.** An office user with `finance.read` (opted in, receiving emails) is
   changed to `designer` (no `finance.read`) between one week's digest and the next. Assert: they
   are dropped from the recipient list for the next digest without needing to opt out, and
   `digest.list`/`digest.get` starts returning `FORBIDDEN` for their session going forward.

5. **`isSampleWorkspace` cache interaction with the sweep.** The sweep must skip sample workspaces
   entirely (no digest row at all, not a `skipped_quiet` one). Confirm the cache
   (`clearSampleWorkspaceCache`, used in wave 18's prod-mode test) doesn't let a *just-converted*
   sample workspace slip through for one more sweep cycle — a variant of wave 18's own caching gap.
