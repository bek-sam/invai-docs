## The specific things I was asked to check
- **T-4-2's outbox `isAlreadyApplied` edit** (`outbox.ts`): before, only `"scan"` was excluded from the "CONFLICT/INVALID_TRANSITION means already applied" heuristic; now `"packOrder"` is excluded too. This is **safe for the other command kinds** — `qc`, `assignBin`, `releaseBin`, `reprint` and the receiving commands are untouched by this change and keep exactly the old behavior (a replayed QC pass that already landed still reads as "already applied" on `INVALID_TRANSITION`/`CONFLICT`, which is correct since those commands have no real idempotency key). `packOrder` is different: it *does* have a real key, and the contract stores results keyed by it (a genuine replay returns the stored result, not an error) — so a `CONFLICT` on `packOrder` can only mean a real business refusal (order on hold, or a stale/reused key on a different order), never "this already succeeded." Excluding it from the heuristic is correct, and `packOrder.test.ts`'s "a CONFLICT (order on hold) is parked, not counted as already applied" test proves it (`report.sent === 0`, `report.parked[0].errorCode === "CONFLICT"`).
- **Decision 0010 flow**: verified end to end (code + live E2E + screenshots): a short order blocks, "Hand to lead" only renders for `production.override` holders, the override doesn't change order status (server side, T-4-1, already reviewed separately) and the floor client correctly reads `packed:false` + non-null `override` as "handed," clearing the station. The offline "saved, not checked" state (`floor.pack.queuedTitle`/`queuedBody`, screenshot `en-9`) and the later replay park for a short order (screenshot `en-10`/`en-11`, alert text "The server BLOCKED it: units of the order are still missing") both work as designed.
