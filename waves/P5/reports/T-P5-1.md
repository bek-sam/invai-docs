## Built
- `invai-backend/src/db/seed/builder.ts`: `plan.qcFail` was an order-level roll but was checked
  per item with a per-item-scoped guard, so every item on a qcFail order that reached "packed" got
  the reprint detour — full-order reprints, 0% partial (today's bug). Added an order-scoped
  `orderQcFailApplied` flag so only the first eligible item per order gets it; siblings press
  straight through.
- Same file: the closed-history forced-reprint block picked a flat `candidates.slice(0, 40)`
  (could include multiple items of the same order). Replaced with a grouped query
  (`GROUP BY order_id HAVING count(*) >= 2`, one item per order via `min(id::text)`), raised to
  `HISTORICAL_REPRINT_TARGET = 160` to land the overall share in the 2-4% band, and renamed/
  commented accordingly.
