# Report: T-P3-3 es money grouping
Author: product-designer on Claude Opus 5.5

## Built
- `formatMoney`/`Money` in `invai-ui/src/app/money.tsx` now shows a group separator for `es`
  4-digit amounts, matching 5+-digit ones; `en` and every other digit count are unaffected
  (`invai-ui/src/app/money.tsx`).

## Key finding (changed the approach)
The card's literal instruction — set `minimumGroupingDigits: 1` — is not implementable here:
**the installed runtime doesn't support that option at all**, not just the types.
- Types: `minimumGroupingDigits` does not exist anywhere in TS 7.0.2's lib files (checked
  `lib.es5.d.ts`, `lib.es2020.intl.d.ts` .. `lib.esnext.intl.d.ts` in
  `node_modules/.pnpm/typescript@7.0.2/node_modules/@typescript/typescript-darwin-arm64/lib/`).
- Runtime: on Node 24.21.0 (V8 13.6, ICU 78.3), passing `minimumGroupingDigits` to
  `Intl.NumberFormat` is silently ignored — it never appears in `resolvedOptions()` and has no
  effect on `format()` output (verified with a throwaway script).
- A cast (`as any`) to force the property past the typechecker would still do nothing at runtime,
  so it wasn't a type problem to work around — the behavior itself isn't there.

Fix instead: `formatMoney` uses `formatToParts` to detect the specific case (an `integer` part with
no `group` part at all — this only happens for exactly 4-digit `es` amounts; I checked 3–10 digit
amounts and negatives), and re-groups those digits itself using the locale's own separator
character (sampled once per cached formatter from a 5-digit amount, so it's never hard-coded to
`"."`). `en` already groups at 4 digits and takes the untouched `!parts.some(group)` → false path,
so it is provably unchanged.

Also found while testing: the separator before "US$" in `es` currency strings is U+00A0 (NBSP), not
a regular space — the pre-existing test on line 26 already had this right; my new test strings use
the same NBSP byte (confirmed with `od`/`python3` byte checks, not visual inspection).

## Decisions
- Manual re-grouping via `formatToParts` instead of a locale swap (e.g. `es-MX`, `es-AR`, `es-US`):
  every regional Spanish locale I tried either uses the American separator order (`es-MX`, `es-US`,
  `es-419`, …) or puts `US$` as a prefix with a space (`es-AR`, `es-CO`, `es-UY`, …), which would
  change the suffix "16.468,39 US$" style pinned by existing tests and the T-A6 screenshots across
  the app. No regional variant I found keeps the suffix style AND fixes the 4-digit gap.

## Known gaps and follow-ups
- `invai-web/src/components/digest/digest-copy.ts:79-80` (`digestMoneyLang`) overrides the locale
  passed into `formatMoney` to `"es-US"` specifically because bare `"es"` used to format USD
  inconsistently ("the same one `digest-copy.ts`'s `digestMoneyLang()` already had to special-case"
  per this card). That inconsistency is now fixed at the source, so the digest's override may be
  redundant — worth a follow-up card for its owner to decide whether to drop it and use plain `"es"`
  (tech lead to route).
- Web/floor formatters that bypass `money.tsx` (per the card, for the tech lead to card to
  web-engineer):
  - `invai-web/src/lib/format.ts:283-291` (`formatMoneyShortLocale`) — own `Intl.NumberFormat` with
    `notation: "compact"`; compact notation sidesteps this exact grouping bug but is still an
    independent currency formatter.
  - `invai-web/src/features/finance/order-profit.tsx:147-148` (`dollars` helper) — own
    `Intl.NumberFormat(undefined, {...})`; not even locale-aware (uses the browser's default
    locale), so it would carry this grouping gap if the default locale is Spanish.
  - `invai-web/src/features/analytics/shared.tsx:152-156` (`formatPoints`) — own
    `Intl.NumberFormat("es"/"en", {...})` for point deltas (not currency), but shares the same CLDR
    grouping-quirk risk for large values.
  - `invai-web/src/components/digest/digest-copy.ts:66-70` (`localeNumber`) — own
    `Intl.NumberFormat`, already uses `"es-US"` to dodge this family of issues (see gap above).
  - `invai-floor`: no independent `Intl.NumberFormat` call sites found (`grep -rn "NumberFormat"
    invai-floor/src/` — no hits); it only consumes `Money`/`formatMoney`.
