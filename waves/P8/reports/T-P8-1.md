## Built
- `invai-infra/infra/execution-role.ts` (new): pure helper, no SST globals. `stageParameterArn()` returns `arn:<partition>:ssm:<region>:<account>:parameter/invai/<stage>/*` and refuses an unsafe stage, account, region or partition. `executionRolePolicy()` returns one statement, `ReadOwnStageSsm`, with `ssm:GetParameters`, `ssm:GetParameter` and `ssm:GetParameterHistory` on that ARN only.
- `invai-infra/sst.config.ts`: one `executionRole` transform object, built with `$resolve([aws.getPartitionOutput().partition, region, aws.getCallerIdentityOutput().accountId])` and `stage = $app.stage`. Nothing is hard-coded. `Imaging`, `Api`, `Worker` and `Migrate` all pass `transform.executionRole` (Migrate got a `transform` block, the other three got one key added).
- `invai-infra/README.md`: one bullet on the IAM scope under "AWS (SST)".

## Decisions
- I used an object transform, not a function transform. It replaces SST's inline policy and leaves nothing to edit inside a stock JSON Output. Recorded here only, since the decision stays inside `invai-infra`.
- I kept all three SSM actions, as the card asks. `ssm:GetParameterHistory` isn't needed by ECS, so it could be dropped later. SecureStrings use the AWS-managed `alias/aws/ssm` key, so the role needs no extra KMS grant.
