# Report: T-27-4 Shopify adapter: push product images (mock + live), idempotent
Author: integrations-engineer on opus. Commit invai-backend `3f4deae` (not pushed).

## Built
- `ChannelAdapter.pushProductImages?(conn, {productGid, images:[{url, alt, filename}], idempotencyKey}) -> {pushed:[{filename, mediaId}], skipped:[{filename, mediaId, reason:"already_pushed"}]}` plus `ProductImagePushError(code, message, outcome)`. Codes: `product_not_found | reconnect_needed | rejected | invalid_input`. Outcome: `not_done | partial`. Transient failures stay `UPSTREAM_FAILED` (retry them). Only Shopify implements it (`channels/types.ts`, `index.ts`).
- Live (`shopify/media.ts`, wired in `live.ts`): read `product.media(first:250)`, skip images already there, send one `productUpdate(product:{id}, media:[{originalSource, alt, mediaContentType: IMAGE}])`, then map the new media ids in input order. The existing `shopifyGraphql` client handles cost-bucket waits, 429/THROTTLED backoff and 5xx retries.
- Dedupe on retry (`productUpdate` has no `@idempotent` directive): a processed media matches by the filename stem in its CDN URL (Shopify may add `_<uuid>` or re-encode the file). A media still processing (image null) matches by exact alt. `FAILED` media don't count.
- Input checks (live and mock): a Shopify product gid; a filename `[A-Za-z0-9_-].jpg|png|webp` that is the URL's last path segment (Shopify names the file from the URL); https; unique; alt at most 512 chars; at most 50 images; a non-empty key.
- Mock (`shopify/mock.ts`): store keyed by (connection, product, filename), giving a deterministic media gid; a repeat returns `skipped`. A product id under 10 digits (`MOCK_SHOPIFY_MISSING_PRODUCT` = `gid://shopify/Product/404`) gives `product_not_found`. Seed and mock listing ids (14e8+, 81e8+) all exist.
- Scope: `write_products` added to `SHOPIFY_SCOPES` (`common.ts`) and `shopify.app.toml`.

## Decisions
- `productUpdate` media instead of `productCreateMedia` (deprecated) or `fileCreate` (would add `write_files`): one scope, one mutation.
- A typed error class (like `CarrierError`) instead of ORPC errors, so T-27-3 can map codes to `PhotoPush.error` or status and knows what to retry.

## Scope change: owner action (tech lead files it in the inbox)

## Round 2 (reviewer r1 finding 1: processing media matched by shared alt)
- Fix (`channels/shopify/media.ts`): the alt sent to Shopify ends in a per-image marker `[img <8 hex of sha256(filename stem)>]` (`altMarker`, `shopifyAlt`; base alt trimmed so the total stays within 512). A processing media (`image` null) now matches only by that marker, and every existing media is claimed by at most one image. Post-mutation mapping uses filename or marker. Interface unchanged (doc line in `types.ts` updated).
- Why the alt: the pinned 2026-07 MediaImage docs say `image` is null until READY and document no other per-file field readable while processing (`originalSource` has no stated availability), and there is no filename field; the card names "alt marker" as allowed. Cost: screen readers hear the 15-char marker at the end of the alt.
- Tests (`media.test.ts`, +5, identical alts): new set while a same-alt set is processing → both added, sent alts carry distinct markers; partial processing → one skipped, one added; retry with 3 processing → 3 distinct media ids, no productUpdate; plain-alt processing media (no marker) not taken; marker stable/unique/512 cap.

## Follow-up (mock http)
- Found while building T-27-3: `validateProductImages` (`channels/shopify/media.ts`) rejected non-https URLs for the MOCK adapter too, so local MinIO presigned URLs (`http://localhost:9000/...`) failed in dev, the gate and E2E.
- Fix: `validateProductImages(input, opts)` takes `{ allowLocalHttp?: boolean }`; mock.ts passes it, live.ts (via `pushShopifyProductImages`) doesn't, so live stays https-only. Allowed hosts are `localhost`/`127.0.0.1` only, not "any http when not production" — the mock also runs under CI/demo envs we don't fully control, and a blanket non-production exception could let a misconfigured non-local http host through unnoticed.
- Tests (+3, `media.test.ts`): mock accepts `localhost` and `127.0.0.1` http, rejects a non-local http host; mock still rejects junk (non-URL, `ftp:`, `file:`); existing live http-rejection case untouched.
