## Decisions
- `photos.sampleScenesNote` is now shown only once `lifestyleCount > 0`, not unconditionally whenever the fieldset renders. Found via `pnpm e2e`: the existing wave-26 test `e2e/listing-photos.spec.ts` asserts `getByText("Sample", {exact:false})` resolves to exactly one element (the "Sample analysis" badge); showing my note unconditionally made that a strict-mode failure. The card's AC1 doesn't require the note before the shop has engaged with scene count, so gating it behind `count > 0` is a reasonable product call that also keeps the existing QA-owned test green without touching `e2e/**`.
- No contract field exposes the image-gen provider to the UI (only `DesignPhotoAnalysis.source` for the vision model). I reused `analysis.source === "mock"` as the signal for "sample scenes", consistent with how wave 26 already labels the same mock state "Sample analysis". In this environment both are mock together (keys blanked), but they are technically different providers; flagging for the architect/product-designer in case a dedicated field is wanted later.
- Extra-credits line is computed by calling `photos.estimate` twice (with and without `lifestyle`) and diffing `credits`, instead of hardcoding `PHOTO_SCENE_CREDITS` on the client — keeps the UI from drifting if the backend constant changes.
- Push target picking is one combined listbox (listing + its connection), not a two-step "pick connection, then product" wizard — `PushTarget` already carries `connectionId`/`connectionName`, so one choice fully determines `pushToShopify`'s `connectionId` + `productRef`.
