# Report: T-27-1 Image-generation provider (mock default, OpenAI behind a flag) with caps
Author: ai-engineer on opus. Commits (invai-backend, not pushed): 83ca734 (stubs + env), 927ad35 (provider, caps, prompts, tests), cfd35ea (eval, faster mock). invai-docs: runbook + this report.

## Built
- `src/ai/images/`: `getImageProvider` (mock unless `IMAGE_GEN_PROVIDER=openai` and `OPENAI_API_KEY` are set and the company isn't a sample workspace), `ImageProvider`/`ScenePrompt` types, `ImageGenError` (`retryable`, `status`) and `ImageRefusalError` (subclasses of the gateway's typed errors).
- `openai.ts`: Images API `edit` with the base, the mask, the prompt, `n:1`, a fixed size, `quality: medium`, png, opaque. No `user` and no `input_fidelity`. Client built only from env's key, `maxRetries: 0`, 120 s timeout. One retry, on a 5xx only. 429 → retryable; timeout, other 4xx and a second 5xx → not retryable; a moderation 400 → refusal.
- `mock.ts` + `png.ts`: a deterministic scene (backdrop, light spot, props per scene kind) replaces the base's background. The garment stays in place (fit and centered at 1024², 1536×1024 or 1024×1536). The whole frame gets light falloff and ±2 noise. `IMAGE_GEN_MOCK_DRIFT` paints stripes over the protected box and a ring around it. 0¢. Uses a zlib PNG codec, so no new dependency. About 0.4 s per scene.
- `caps.ts`: `assertImageGenAllowed(tx, companyId, count, {heldCredits, provider, sizePx})` checks in order: the daily cap (today's done `image_scene` ai_jobs rows, UTC; mock rows count), then `CREDITS_EXHAUSTED` (`PHOTO_SCENE_CREDITS`×count plus held credits), then `AI_SPEND_CAP_REACHED` with the estimate (real provider only). `recordImageGen` writes one ai_jobs row (provider, model, cost, prompt ref, credits 0), then calls `recordSpend` after the commit.
- `scene-prompt.ts`: `buildScenePrompt` builds the prompt from fixed vocabulary only. Analysis text is matched against word lists, never copied. The blank name is reduced to an allowlist of color words. The constant rules block (print area left blank, no text or logos or brands, no real people, celebrities or children, adults only) always comes last. `containsPerson` comes from the scene kind, or from an analysis suggestion for that kind (conservative).
- `models.ts`: `OPENAI_IMAGE_MODEL = gpt-image-2`, a per-image price table, an input allowance, `imageCostCents`. `breaker.ts`: optional `estimateCents` on `assertSpendAvailable` (default 0 keeps the old behavior). `db/schema/ai.ts`: job kind `image_scene` (enumText; `drizzle-kit generate` → "No schema changes").
- env (granted lines only): `IMAGE_GEN_PROVIDER`, `IMAGE_GEN_DAILY_CAP_PER_SHOP` (default 30), `IMAGE_GEN_MOCK_DRIFT` (boot fails outside test). Production with `openai` and no key, or a blank key, refuses to boot. Commented lines added to `.env.example`. Runbook: three env rows plus "owner turns it on (OI-25)".
- `evals/scene_prompts/` (14 cases) + `pnpm evals scene-prompts` alias.

## OpenAI facts confirmed (2026-10-03)
- SDK `node_modules/openai` 7.25.0 `resources/images.d.ts`: the mask is a PNG with the same size as the image, alpha 0 = edit area. `input_fidelity` is high|low and ignored by gpt-image-2. Standard sizes 1024x1024, 1536x1024, 1024x1536 (gpt-image-2/2.5 also take arbitrary WxH). quality low|medium|high (xhigh|max on 2.5 only). `user` is optional, and we never send it.
- developers.openai.com/api/docs/guides/image-generation: "Masking with GPT Image is entirely prompt-based … may not follow its exact shape". For gpt-image-2, omit input_fidelity. Medium price per image: $0.053 at 1024², $0.041 at 1536×1024 and 1024×1536. The guide recommends gpt-image-2.5 for new integrations, but 2.5 has token prices only ($8 in / $30 out per MTok, from the /pricing page), so it is a later model-upgrade.
- Cost per scene = output price + a 5¢ input allowance (base + mask at high fidelity, an estimate) → 11¢ at 1024², 10¢ at the other two sizes. Reconcile against the first real invoice.

## Decisions
- Model gpt-image-2 at medium quality: published per-image prices; the scene is only a backdrop. Moving to 2.5 goes through `model-upgrade`.
- The cap is counted from ai_jobs, not reserved. Scenes in flight can pass it by up to the job concurrency. Credits and the spend breaker still hold.
- `recordImageGen` charges no credits. The photos module charges once per scene with its own guard (ADR 0023 §5).
- Timeouts are not retried: the call may already be billed.
