## Built
- `sign_in_failures` (HMAC-SHA256 of trimmed+lowercased email, never the address), `password_history`, `users.mfa_grace_starts_at` (NOT NULL DEFAULT now(), metadata-only); env `ACCOUNT_LOCK_THRESHOLD` 10 (max 10), `ACCOUNT_LOCK_MINUTES` 30, `MFA_GRACE_DAYS` 7 (0–14); `.env.example` synced.
- Lockout (`src/lib/account-lockout.ts`, wired in `src/auth.ts`): before-hook on `/sign-in/email` throws `ACCOUNT_LOCKED` 423 + `retryAfterSec` + `Retry-After` before the endpoint (no session); after-hook counts `INVALID_EMAIL_OR_PASSWORD` with one atomic upsert, clears on success; the failure that reaches 10 sends the one en/es lock email (`notified_at` guard), warn log with user id only; reset clears the row. Unlocked failures stop counting 24 h after the last one; stale rows swept on insert.
- Password history (`src/lib/password-history.ts`): recorded in `databaseHooks.account.create/update.after` + `onPasswordReset` (Better Auth's reset uses updateMany, whose hook gets no row); refused in before-hooks of `/change-password` (only after the current password verifies: no old-password oracle) and `/reset-password` (user from `reset-password:<token>`, token not consumed) with `PASSWORD_REUSED` 400; ≤10 rows/user, cascade on user delete.
- MFA (`src/lib/mfa.ts`): `Membership.demo` in context; `context.mfa` for user sessions; guard check after permission, before EMAIL_NOT_VERIFIED, user/floor-mode procedures with a user session only; `MFA_EXEMPT_PROCEDURES = {me.get, me.switchOrg}`; `me.get` returns `mfa` (omitted for floor); `/two-factor/disable` → `MFA_DISABLE_NOT_ALLOWED` 403 while required; grace restart on `changeRole`, reactivation (`setMemberStatus`), invite accept, org create.
- Docs: backend README "Account security (auth)" section; modules README helper row (role rule for new `src/lib` helpers; file is role-owned, not listed on the card).
