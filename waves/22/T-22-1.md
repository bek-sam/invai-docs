## Acceptance criteria (all additive; new fields optional; minor version bump)
1. Shipping: `shipping.scanForms.create({carrier, date?})` / `.list(Page)` / `.get({id})` returning a SCAN form with its label count and a file id (B-25); `shipping.verifyAddress({orderId})` returning `{status: verified|corrected|failed, suggestion?}`; `Rate.expiresAt` (rate TTL).
2. Production: QC fail reasons go through the **existing** `production.qc` procedure and its `reprintReason` field (no new `qcFail` procedure; extend the enum only if a reason is missing, additively; architect A2). `Transfer.printedAt` + `ageDays` on pick/press views. Station maintenance: `production.maintenance.start/end/list({stationId, reason})` backed by a production-owned `station_maintenance_events` table (not the tenancy `stations` table; architect A3). A scan on a station under maintenance returns `ScanResult` with a new `MISMATCH_REASONS` value `station_maintenance` (scans never throw for business outcomes; architect A4) (B-35).
3. Inventory: pick-list line carries `binCode?: string` and `shelf?: string` (B-32).
4. Vendors: `vendors.sheets.resendEmail({sheetId})` (idempotent per sheet + day; `org.manage` or the existing vendor permission) (B-102).
5. Settings: `OrgSettings.shipsSaturday: boolean` and `printsInHouse: boolean` settable through the existing settings procedure (B-162) if not already settable; say which.
6. `CHANNEL_RULES.tiktok.fees.transactionPct` = 6 with the source URL and date in a comment; `schemas.test.ts` updated with the evidence (B-164). `ListingContent.attributes` aligned with the backend shape, with a plan for the DB default (B-167; if it needs a breaking change, write an ADR and stop at a proposal).
7. `pnpm typecheck && pnpm lint && pnpm test` green in contracts; consumer typecheck (`backend`, `web`, `floor`) still passes against the new version (backend stubs listed in the report).
