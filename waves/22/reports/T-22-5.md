## Built
- **Import races (B-99):** `importNormalizedOrders` takes `pg_advisory_xact_lock(hashtextextended('order_import:<connectionId>'))`; `createOrder` inserts with `ON CONFLICT (company_id, channel, channel_order_id) DO NOTHING` and falls back to the update path on a conflict (`orders/import.ts`).
- **Money on re-import (B-197, AC7):** `mergeTotals`: a 0 never replaces a stored subtotal/shipping/tax/total; discount is kept only for a price-less payload; units added from a price-less file take the line's known price.
- **Line edits (AC2):** already built in T-7-4 (`applyLineEdits`): unrouted units change in place; routed ones get replaced (cancel + scrap, audited); pressed/packed units are never changed and get the `channel_edit_after_press` flag. Covered by `import-edits.test.ts` (6 tests); no code change.
- **Vendor delivery (B-102):** new table `vendor_sheet_deliveries` (RLS, composite FKs to `gang_sheets` and `vendor_connections`, unique `(company_id, gang_sheet_id, seq)`; migration `0034`). `sendSheetToVendor` now writes a `pending` row plus `sheet.sent` and sends nothing itself. Job `vendors.deliverSheet` (ship queue, jitter) handles `sheet.sent` and the internal `vendor.sheet_resend_requested` and works in 3 steps: claim `sending`, send with no transaction open (45 s race), record `sent`. SMTP error → `pending` + retry. 5xx or last attempt → `failed`. A `sending` claim older than 50 s → `unknown` and **not re-sent**, because SMTP has no read-back. `vendors.sheets.resendEmail` is off the stub. It locks the sheet and returns the errors `SHEET_NOT_SENT`, `VENDOR_USES_PORTAL` and `RESEND_TOO_SOON` (`retryAfterSec`, `lastSentAt`; 10 min from the last send/request; a `failed` row doesn't count) (`vendors/delivery.ts`, `jobs.ts`, `router.ts`, `service.ts`).
- **TikTok 6% (B-164):** contracts `git cherry-pick 81afad4` → `9e8ea0c`; `fees.test.ts:90` → 6 with the source; profit test with the source; custom migration `0035` moves saved cost-settings tiktok entries at exactly 8 to 6.
- **Attributes (B-167, ADR 0017):** `foldAttributes` in `ai/service.ts` (trims keys, drops empty keys, first key wins, `__proto__` stays data) + `listing-attributes.test.ts`.

## Exercised for real (API :3125, worker, dev copy `invai_t22_5dev`, shop renamed "… T-22-5")
- Office sends sheet 1 to an email vendor with the worker stopped → 200, row `pending`, no mail. Worker started → `sheet delivered` → 1 mail "Gang sheet T-22-5 sheet 1 …". Duplicate enqueue (`t225-dup-1`) → `{"status":"skipped","reason":"nothing_pending"}`, still 1 mail.
- Sheet 3 with the worker on a hanging SMTP: row `sending`, `kill -9` of the worker, new worker → "job stalled; it will run again" → "outcome unknown, not resending", 0 duplicate mails.
- Sheet 2 against a closed SMTP port: `ESOCKET` ×5 → `failed`. Resend → 200 (window not started), 1 mail. Second resend → 429 `RESEND_TOO_SOON` `retryAfterSec 600`. Sheet 1 → 429 (299 s). Presser → 403 `FORBIDDEN`. Portal sheet → 409 `VENDOR_USES_PORTAL`. Unknown id → 404.

## Decisions
- At-most-once for an uncertain send (`unknown`, office resends) over a possible second copy. The resend window counts from the request, so two clicks can't both send.
- A new table, not columns: the sheet row belongs to production. The resend uses an internal outbox event (precedent: `sheet.regenerate_requested`), so no contract change was needed.
- 0035 changes every tiktok entry at exactly 8; a shop that really typed 8 is changed too (can't be told apart; the tech lead's instruction).
