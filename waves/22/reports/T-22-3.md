## Built
- **SCAN forms (B-25).** `shipping.scanForms.create/list/get` replace the day-1 stubs. Create claims (company, carrier, shop-local date) with a `creating` row listing the eligible labels (carrier match, `labeled`/`in_transit`, labeled that day in the shop's timezone, not voided, not on any form), commits, calls the carrier with no transaction open, then records the form id and PDF key. A repeat returns the stored form. A carrier refusal deletes the claim and answers `SCAN_FORM_REJECTED {detail}`; an unknown outcome keeps the claim and the retry reads back (`scanFormOf`) before creating, since a shipment can be on one form only; a create in flight answers `CONFLICT`. `get` fills in a PDF EasyPost finished rendering later. PDF key `{companyId}/label/scanform-{id}.pdf` (the `label` kind: shipping roles only). (files: `src/modules/shipping/{service,router}.ts`, `src/integrations/carriers/{types,index}.ts`, `easypost/index.ts`, `mock/index.ts`)
- **EasyPost adapter:** `POST /v2/scan_forms {shipments:[{id}]}` (never auto-resent on 429), read-back via `GET /shipments/{id}` → `scan_form` → `GET /scan_forms/{id}`; the form PDF is downloaded only from EasyPost hosts, `redirect: "manual"`, 10 MB cap. `POST /v2/addresses {address, verify: true}` (429 retried with jitter; it charges nothing). Doc URLs and check date at the top of the file.
- **Mock carrier:** deterministic address fixtures (failed: bad ZIP or `000xx`; corrected: spelled-out street suffix → USPS form, upper case; else verified); SCAN form as a one-page PDF (date, count, tracking codes, no buyer data); membership stored per carrier shipment so seeded labels (no mock record) can be manifested once.
- New carrier calls live on `CarrierExtras` / `carrierExtras(scope)` (same live/mock/sample-workspace selection) instead of widening `CarrierAdapter`, which would have broken 7 test fakes owned by others.
- **Address check (B-25).** `shipping.verifyAddress`: `NO_SHIP_TO` without a ship-to; result stored in `address_verifications` (status, carrier reason, time, keyed HMAC of the address; **no address at rest**). A repeat on the same address returns the stored result without a carrier call; a repeat of `corrected` asks the carrier again for the suggestion instead of storing it. `failed` holds the order (`address_check`) through `orders.holdOrder` in a savepoint (skipped if already held, shipped or cancelled; a refused hold is logged, the result still commits). Logs carry ids and status only.
- **Rate TTL (B-25).** `src/integrations/carriers/rate-ttl.ts`: expiry = rated + 24 h, cut at the next carrier price change (USPS Oct 4 2026 and Jan 18 2027, UPS Jan 17 2027, Central midnight). Every `Rate` returns `expiresAt`. `buyLabel` on an expired quote re-rates first; same carrier+service at the same price is bought on the fresh quote, a moved price or vanished service answers `RATE_EXPIRED` ("The price for this service changed…") with the new quotes stored. One re-rate per buy (`rerated` flag), no loop.
- **Storage:** `scan_forms` and `address_verifications` in `src/db/schema/shipping.ts`, migration `drizzle/0032_shipping_scan_forms.sql` (RLS + tenant policy on both, composite `(company_id, order_id)` FK per T-22-2's pattern, unique `(company_id, carrier, date)` and `(company_id, order_id)`). Only my two tables are in the migration.
- **Amazon CSV (B-183).** Root cause, with evidence: the parser has mapped `shipping-price` → `orders.shipping_cents` all along. Zeros come from (a) Amazon's **Unshipped Orders report has no price columns at all** (27 columns; developer-docs.amazon report-type-values-order, page updated 2026-09-09, checked 2026-09-29), so every Unshipped import gets 0 items and 0 shipping; (b) the demo seed hardcodes Amazon shipping to 0 (`src/db/seed/builder.ts:800`), which is what the metric note measured. The **Order Report** (36 columns) carries `shipping-price` per line and imports correctly. Added two synthetic fixtures built from the official column lists (`amazon-order-report.txt`, `amazon-unshipped-orders-official.txt`), a parser test (multi-line order sums 399+200, free shipping 0, accents, latest-ship-date as ship-by, Unshipped → 0 documented) and an import test that reads `orders.shipping_cents` back (499/599/0). Corrected the parser's doc comment. No mapping change was needed.
- **Mailer (B-139).** Logs `template` (new optional `Mail.template`) and `subjectHash` (16 hex of sha256), never the subject, on all four log lines; `template` is stripped before nodemailer. (file: `src/integrations/vendors/mailer.ts`, test `mailer-subject.test.ts`)

## Decisions
- `CarrierExtras` interface beside `CarrierAdapter` (keeps others' fakes untouched).
- No corrected address stored; keyed HMAC (`BETTER_AUTH_SECRET`) decides "same address". Less PII at rest, no purge change needed; costs one free carrier call per repeat of a `corrected` result.
- `address_verifications` table: the grant named SCAN-form storage; storing the address result (AC2) needed a table too, so it went in the same shipping schema file and migration. **Flag for the tech lead and backend-foundation:** accept or ask me to move it.
- Rate TTL kept at 24 h (the existing value) plus price-change cut-offs; price changes are a data list in `rate-ttl.ts`, to be updated by provider-deprecation-watch.
- SCAN form eligibility includes `in_transit` (the mock moves labels there within minutes); one form per carrier+day per the contract, so labels bought after the day's form wait for the next day's form.
- `holdOrder` loaded with a dynamic import (orders/service already imports shipping/service).
