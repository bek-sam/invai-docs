Author: ai-engineer on Opus 5.5. Backend commit `33c09fd` (not pushed).

## Threat model (short; flag: payments / AI spend, LLM10)
- Entry: `ai.assistant.ask` (user session, permission `ai.assistant.ask`); tenant from session. No new data to the provider, no new tool, no contract change.
- Worst outcome before: one question runs 10 rounds after the shop or platform cap is spent (one shop's bill, or every shop paused late). Control now: per-round `recordSpend` + `assertSpendAvailable` + `assertCredits` in the gateway before the next request (test `assistant-rounds.test.ts`).
- Accepted risk: parallel questions can overshoot a cap by at most one round each (R3). Valkey down still fails open with the existing alert.

## Built (invai-backend/src/ai only)
- `providers/types.ts`: provider-internal `AssistantRoundEvent`; `AiProvider.assistant` yields `ProviderAssistantEvent`. `runAssistant` still yields `AssistantStreamEvent` only, so `modules/ai/service.ts` and the contract are untouched (the round type is kept off `AssistantStreamEvent` for that reason, a small deviation from R3's wording).
- `providers/anthropic.ts`: yields `{type:"round", usage(cumulative), model, stopReason}` after `finalMessage()` + `checkStop`. SDK checked: `BetaToolRunner.mjs:160-235` sends the next request only when pulled; its `finally` aborts on `return()`.
- `providers/mock.ts`: typed `Omit<AiProvider,"assistant"> & {assistant: typeof mockAssistant}` so the mock (which never yields rounds) keeps its narrow type for existing tests.
- `gateway.ts` `runAssistant`: `afterRound` records `tokensToCostCents(usageSoFar) - recordedCents`, then on `tool_use`/`pause_turn` only checks `assertSpendAvailable` and `assertCredits(tokensToCredits(usageSoFar)+1)`. On a trip, `stopMidRun` closes the provider, `finishJob` with the usage so far (status done, `stop_reason` `spend_cap` / `credits_exhausted`, credits charged once, `onSettle` fired), and rethrows; `failJob` is skipped. `finishJob` records `max(0, costCents - recordedCents)` on every path, including disconnect.
- Market-answer regeneration (a second model pass): the caps are checked before it and between its rounds; when spent, the turn ends with the tools' own `fallbackAnswer` (no error, job `stop_reason` `spend_cap`).
