## Threat model (short)
Callers: every agent's Bash (PreToolUse guard) and PostToolUse/Failure tracker. Worst outcomes: (a) a broken guard denies every command for the team (fails closed) → built and tested in /tmp/p7-4-hooks, installed by atomic rename after 105/105 green; (b) a blocked action slips through a script, decoded text, `sst secret` or `gh api` write → AC1–AC3 rules + tests; (c) Stop gate skipped after a shell edit → AC4; (d) false denies stall agents → real team scripts and commands in tests. The guard stays a denylist for mistakes, not a sandbox.

## Built (live `.claude/hooks/` = backup `invai-docs/team/hooks/`, `diff -q` clean)
- guard-bash.py AC1: `bash|sh|zsh <file>`, `source|. <file>`, `./<file>`, `<path>/*.sh` → file read (≤256 KB text; larger denied; binary/missing skipped), nested scripts too (read once each, max 32), every rule applied with the same message. Missing script that the same command also names (written then run) → denied: "write it in one call and run it in the next".
- guard-bash.py AC2: decoder (`base64|base32|basenc -d/-D/--decode`, `openssl base64|enc -d`, `xxd -r`, `uudecode`) + executor (shell reading stdin or `-c`, `eval`, `source`, `.`) in one top-level segment → denied. Decoding to a file or into `tar` allowed.
- guard-bash.py AC3 (word-level, so commit messages don't trip): `sst secret set|remove|load` (also via pnpm/npx/exec/.bin), `gh api` writes (-X/--method POST|PUT|PATCH|DELETE, or implicit POST from -f/-F/--field/--raw-field/--input) to `repos/<o>/<r>`, `…/protection`, `rulesets`, `collaborators`, `hooks`, `environments`, `transfer`, `actions/permissions`, GraphQL repo-setting mutations, `gh repo edit|delete|rename|archive|unarchive`, `gh ruleset` other than list/view/check.
- guard-bash.py fix found on the way: shlex comments ran past newlines (newlines become `;`), so after any `#` (`# note`, `a#b`, `${#x}`) the rest of a multi-line command went unread by the word rules. Now comments are stripped quote-aware first.

## Decisions
- AC4 text-based, not a `git status` fingerprint: a fingerprint needs a PreToolUse snapshot of 7 repos per Bash call and would blame this agent for other agents' concurrent edits in the shared tree; text only records what this agent's command names. Cost: writes by programs it can't see (codegen scripts, node/python) aren't counted.
- >256 KB script text is denied (fails closed) rather than skipped. `bash invai-infra/scripts/dev.sh` run directly now asks the owner (it runs `pnpm install`); `pnpm dev:all` is unchanged.

**What enforces this:** the guard hook (`.claude/hooks/guard-bash.py`) denies:
- force-pushes, ref deletions and tag pushes; pushes by anyone but the tech lead, and code-repo pushes without a fresh `pnpm gate` stamp
- remote or history rewrites
- deploys (`sst deploy|remove`, `pnpm deploy:*`, `gh workflow run`)

- secret, key and repo-setting changes: `sst secret set|remove|load`, `gh secret|variable` writes, `gh repo edit|delete|rename|archive`, `gh ruleset` writes, and `gh api` writes to a repo, its branch protection, rulesets, collaborators, hooks or environments
- the same commands inside a script it is asked to run (`bash x.sh`, `source x`, `./x`), and decoded text run as code (`base64 -d | bash`, `eval "$(… base64 -d …)"`)

Any MCP tool that isn't clearly read-only (send, reply, publish, create, update, delete) needs the owner's approval on screen. The hook fails closed. It is a denylist for mistakes, not a sandbox: commands built at run time, aliases and node/python subprocesses are out of its reach. The Stop gate (`verify-gate.py`) also counts file writes made through Bash (`sed -i`, `>`, `tee`, `git apply`, `biome --write`, `mv`/`cp` into a repo) as edits.
