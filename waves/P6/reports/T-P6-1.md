## Built

## Exercised for real
- Scratch DB `invai_p6_reset` created by hand (`CREATE DATABASE`), a sentinel table added.
- `MIGRATION_DATABASE_URL=…/invai_p6_reset REDIS_URL=redis://localhost:6379 tsx src/db/reset.ts` → refused, exit 1, nothing touched.

- `MIGRATION_DATABASE_URL=…/invai_p6_reset tsx src/db/seed/index.ts` with `SEED_OUTPUT_FILE` unset → refused, exit 1, before any table existed; with `SEED_OUTPUT_FILE=/tmp/p6-1-seed-output.json` → guard passed, failed only on an unrelated unmigrated-schema error (expected, out of scope).
- Dropped `invai_p6_reset` at the end; removed `/tmp/p6-1-seed-output.json`.

## Decisions
- Guarded `main()`'s invocation in `seed/index.ts` with the same `fileURLToPath(import.meta.url) === process.argv[1]` pattern already used in `reset.ts`, so the new pure function can be unit-tested by importing the module without triggering a real seed. This is a small structural change beyond "just the guard line" but was necessary for AC5 (unit-testable pure functions); `pnpm db:seed` behavior for the gate/CI (always invoked as the script) is unchanged.
- Duplicated `isPinnedNonZeroRedisDb` logic (matching `env.ts`'s private `isPinnedNonZeroDb`) locally in `reset.ts` rather than importing it, since `src/env.ts` is outside this card's owned paths.
