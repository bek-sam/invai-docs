## Required changes
1. **`me.notifications` shape (wave.md interfaces, T-19-1 AC1).** Keyed by kind, not a `digestEmail` boolean: `NOTIFICATION_KINDS = ["digest"]` (schemas/tenancy.ts, values appended later); `get() → { items: [{ kind, on, source: settings|unsubscribe_link|admin, updatedAt }] }`, `set({ kind, on }) → same`. Permission `org.read` (every role holds it; `none` is reserved for the five bootstrap procedures, `contract.test.ts`). `auth: "user"`.
2. **Plan-usage permission is `billing.read`, not `billing.manage`** (wave.md fences, T-19-1 AC2, T-19-3 AC10). `billing.manage` is `OWNER_ONLY` (roles.ts), so an admin would lose plan usage, against spec "Users" (owner and admin see it; office doesn't). Office lacks `billing.read`, so the fence holds. `digest.settings.*`, `digest.sendPreview`: `org.manage` (owner/admin only; office lacks it).
3. **Recipients procedures are missing** (T-19-5 AC4, T-19-4 AC1 need them). Add to T-19-1: `digest.settings.get` output carries `recipients: [{ userId, name, emailOn, deliverable: ok|unverified|placeholder|suppressed }]` (members with `finance.read` only) and `digest.settings.setRecipientEmail({ userId, on: z.literal(false) })` (`org.manage`; T-19-3 implements by calling T-19-4's `setEmailPreference(..., { on: false, source: "admin" })`). Add both to wave.md interfaces.
4. **Client-visible statuses** (T-19-1 AC3, T-19-3 AC5/AC10). Contract `DIGEST_STATUSES = ["ready", "skipped_quiet"]`; `building`/`failed` are DB-only in `schema/digest.ts` and `list/get/latest` never return them (spec pipeline 1: never a half-built digest). `digest.latest() → { digest: DigestSummary | null, paused: boolean }` so the "paused" line (T-19-5 AC2) has a source.
5. **Shadow text** (T-19-1 AC3 wording). The `Digest` schema has *no* narrative text field in 0.7.0, not an optional one that must be null; only `narrativeStatus`. An optional `summary` is added additively when OI-8 flips the mode. Also add `digest_narrative` to `CREDIT_KINDS` (end of enum, `schemas/ai.ts`) now so T-19-2's credit charge needs no mid-wave contract edit; T-19-2 mirrors it in backend `schema/ai.ts`.
6. **Two day-1 stubs, not one** (T-19-1 Verification, T-19-4 Depends on, wave.md step 2). After T-19-1 the backend fails typecheck in `src/api/router.ts` (`digest`) *and* `src/modules/tenancy/router.ts` (`authed.me.router` must implement `notifications`). T-19-4's day-1 commit includes the `me.notifications` `stubRouter` alongside `notify.ts`/`links.ts` signatures.
7. **Where delivery idempotency lives** (wave.md interface, T-19-4 AC2, T-19-3 AC9). Two layers, each with a durable key: (a) `sendUserEmail` owns an `email_sends` table in `schema/notifications.ts` (`company_id`, `dedupe_key` unique per company, `kind`, `user_id`, `message_id`, `status pending|sent|skipped`, `reason`, RLS): insert `pending` in its own short tx, call the transport outside any tx, mark `sent`; a repeat key returns `{ status: "skipped", reason: "duplicate" }` (add `duplicate` to the reason list). (b) T-19-3's `digest_deliveries` (unique digest, person, channel) is the digest-level outcome row, recorded before the call and updated after, with `dedupeKey = digest:${digestId}:${userId}` and `messageId = <digest.${digestId}.${userId}@<MAIL_FROM domain>>`. Without (a), a worker crash between send and the delivery update re-sends on retry.
8. **Preview bypasses opt-in, nothing else** (T-19-3 AC10, T-19-4 AC2). `sendUserEmail.kind: "digest" | "digest_preview"`; `digest_preview` skips the preference check only, `dedupeKey = digest-preview:${digestId}:${userId}:${minute}`. The `writes` bucket in `api/orpc.ts` is per company and far looser than AC30, so T-19-3 keeps a Redis key `digest:preview:${companyId}:${userId}` (TTL 60 s) and throws `rateLimited(retryAfterSec)` (Retry-After flows through `resHeaders`).
9. **Public link routes, pinned** (T-19-4 AC5, T-19-3 AC11, T-19-5 AC6; README note in T-19-1 AC6):
   - URL `${BETTER_AUTH_URL}/l/:token` (the API's public origin already in env). Drop `PUBLIC_WEB_URL` from T-19-4's env list: `WEB_ORIGIN` exists for web links.
   - Token: `signPayload` with a purpose-bound key `hmacHex(BETTER_AUTH_SECRET, "links:v1")` (no new env), payload `{ v: 1, k: unsubscribe|click, c, u, r (≤ 128 chars), exp }`; unsubscribe expiry 400 days, click 30 days. Verify binds `c`+`u` to an active membership before acting (AC25).
   - `POST /l/:token`: `k = unsubscribe` only (`click` → 405); accepts the RFC 8058 form body or empty; sets the preference off with source `unsubscribe_link`; 200 on repeat. Undo: `POST` JSON `{ undo: true }` on the same token, allowed only within 24 h of that unsubscribe (else 409, the page says to sign in); this is what T-19-5's Undo button calls.
   - `GET /l/:token`: unsubscribe → 302 `${WEB_ORIGIN}/unsubscribe?token=…`, mutates nothing; click → registered handler → 302 `${WEB_ORIGIN}${path}` where `path` starts with `/`, not `//`, no `\` or scheme (else `/`). The API origin has CSP `default-src 'none'`: never render HTML there. Invalid or expired: GET → 302 `${WEB_ORIGIN}/unsubscribe?error=invalid`, POST → 400; the token never appears in logs.
   - `registerLinkHandler("click", (in: { companyId, userId, ref }) => Promise<{ path: string } | null>)`; T-19-3 registers it in the digest module's entry file, which the `src/modules/jobs.ts` grant line loads (app.ts imports jobs.ts, so the API process has it). Per-IP limit: a `links` bucket, 60/min.
