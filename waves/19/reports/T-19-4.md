## Decisions
- `DIGEST_ENABLED` and `DIGEST_EMAIL_ENABLED` default **true**: they are kill switches, and the "no real email" fence is held by `SMTP_URL` (Mailpit outside production, required in production) plus OI-12/13/14; QA's AC23 acceptance test also expects a send with default env. `DIGEST_SUMMARY_MODE` defaults to `shadow` as required. In-card decision; flag if the tech lead prefers `DIGEST_EMAIL_ENABLED=false` by default.
- `email_sends.status` has a fourth value `failed` (beyond A7's `pending|sent|skipped`): a transport error marks the row and rethrows so the caller's job retries and takes the row over; a `pending` row older than 10 min is treated the same (crash between claim and settle). Without it a crash would lose the email for that key forever.
- A skip is recorded on the `email_sends` row, so the same dedupeKey stays `duplicate` even if the person opts in later that week (one outcome per key, as ADR 0016 §5 intends). The kill switch (`disabled`) writes no row, so re-enabling lets a re-run send.
- The kill-switch check reads `env.DIGEST_EMAIL_ENABLED` at call time; the unit test flips it through a typed cast on the env object (`env as { DIGEST_EMAIL_ENABLED: boolean }`) inside try/finally — a test hook, not a type dodge.
- Undo writes `source: settings` (the person chose), so the "unsubscribe_link can only turn off" rule stays a single guard.
- Mailer grant kept the return shape `{ messageId }` (strict `toEqual` in `pin-only.test.ts` / `demo-guards.test.ts`); skips are read back via `mailSkipReason()`. The architect's optional `skipped?` field was tried and reverted for that reason.
- No new ADR: everything follows ADR 0016.
