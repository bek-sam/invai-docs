## Built
- **Shared analyst queries** (`src/modules/ai/analyst-queries.ts`): `comparePeriods`, `adPerformance`, `designInsights`, `fulfillmentHealth` as `(tx, ctx: Pick<TenantContext,"companyId">, input)` data functions, plus `toPeriod`/`previousPeriod` and the thresholds. The caller opens `withTenant`; every query also filters on `ctx.companyId`. `designInsights` returns two extra fields (`designsSold`, `missingCostData`) that the tool strips before the model sees its data.
- **Assistant tools switched** (`assistant-tools.ts`): the four tools call the functions and keep only their text; `previousPeriod` is re-exported for existing callers. Data and answer text unchanged.
- **Route** `digest_narrative` in `models.ts`: Opus 5, effort `low`, `maxTokens` 2,000. `AI_JOB_KINDS` and `CREDIT_KINDS` gain `digest_narrative` (enum text, no migration; `db:generate` not run because other cards' schema work sits uncommitted in the tree).
- **Prompt** `digest_narrative@1` (`prompts/index.ts`): the system prompt holds the rules plus `DATA_RULE`. Insights (id, kind, factIds, trusted template) and facts (id, formatted value) go in one JSON `digest_facts` data block. The output is `{lang, headline, items[{insightId, text}]}` with `{{factId}}` placeholders only.
- **Validator** (`src/ai/validators/digest.ts`): 17 hard-fail rule ids: `schema, language, insight_order, headline_length, item_length, placeholder_syntax, placeholder_unknown, placeholder_foreign, digits, number_words, direction_words, promise, url, email, markup, market_claim, pii`.
  - Rules run on the model's own words with placeholders removed, so shop text like a design name is never judged as the model's claim.
  - Lengths are measured on the substituted text: headline ≤ 90, item ≤ 280.
  - Market words are allowed only in `market` items.
  - Number and direction lists cover en and es. The Spanish article "un/una" is allowed, and "once" counts only in Spanish.
- **`generateDigestNarrative(companyId, {digestId, lang, insights, facts}, now?)`** (`src/ai/digest-narrative.ts`) returns `{status, text?, summary?, failedRules?, cents, mode, showable}`:
  - `off`: returns `skipped_off` with no call.
  - A digest that already has a finished run reuses the stored output: no second call and no second charge (the ledger ref is the digest).
  - Before the call it estimates the cost (whole prompt as input plus the full `maxTokens` as output). If this week's spend plus the estimate is above `DIGEST_MAX_CENTS_PER_WEEK` (default 10), or fewer than 25 credits are left, it returns `skipped_budget`. A `CREDITS_EXHAUSTED` or `AI_SPEND_CAP_REACHED` error from the gateway also gives `skipped_budget`.
  - Any other model error gives `rejected` with `["schema"]` and is never thrown.
  - Any validator failure gives `rejected` with rule ids and one warn log line (the metric). There is no retry.
  - The outcome is stored on `ai_jobs.output.validation`.
  - `showable` is true only in mode `on` with status `ok`.
- **`digestSummaryMode()`** is async, because the breaker state lives in Valkey. It reads `DIGEST_SUMMARY_MODE` (default `shadow`; `on` exists, but nothing sets it). A tripped breaker or an unreadable Valkey gives `shadow` (fails closed).
- **Breaker** `checkDigestSummaryBreaker`: counts `digest_narrative` jobs across all tenants in the last 24 h (`withSystem`, counts only). Failed calls count as rejected. When more than 10% are rejected, it sets the Valkey flag `ai:digest_summary:breaker` (NX, no TTL, cleared by a person) and raises one critical `ai_summary_breaker` alert through `raiseAlert` on the shop whose summary tipped it, plus an error log. It runs after every call.
- **Mock** `mockDigestNarrative`: a fixed label per insight kind (en/es) plus that insight's own placeholders, trimmed to fit 280 characters. It passes the validator by construction.
- **Evals** `evals/digest_narrative/` (22 cases) with `run.ts`, registered in `evals/run.ts` (the import plus one `ROUTES` entry), and a `digest_narrative` entry in `evals/baseline.json`.

## Decisions
- `digestSummaryMode()` is **async** (breaker state in Valkey). Sent to the tech lead with the day-1 commit.
- The mode and cap are read from `process.env` (`DIGEST_SUMMARY_MODE`, `DIGEST_MAX_CENTS_PER_WEEK`), with T-19-4's names and defaults, at call time, so this card doesn't wait on T-19-4's `env.ts`. Follow-up: switch to `env.*` once it lands.
- The validator measures lengths on the substituted text, and treats the headline as free to use any fact. Items may use only their own insight's facts.
- Model errors (refusal, max_tokens, schema) return `rejected` with `["schema"]`, are never thrown, and count toward the breaker.
- Breaker: global counts come from `ai_jobs` with `withSystem` (counts only). The flag has no TTL, so un-pausing is a human decision. The alert goes on the tipping shop, the same pattern as the platform spend-cap alert; the contract kind `ai_summary_breaker` came from T-19-1 on request.
- The rebuild guard reuses a finished run for the same digest. Two truly concurrent builds of one digest could both call; T-19-3's per-week build idempotency keeps that from happening.

## Known gaps and follow-ups
- **Real-model eval (OI-8):** the word lists are strict on purpose. In shadow mode a false reject costs only a template, but the real-model rejection rate must be measured before `on`, because more than 10% trips the breaker. Owner: ai-engineer with OI-8.
- **Contracts dependency:** the backend `CREDIT_KINDS` value typechecks against `modules/ai/service.ts` only with contracts 0.7.0 (`digest_narrative` in the contract `CREDIT_KINDS`); the working tree has it.
- "Skip when nobody will read it / quiet weeks" (pipeline 9) is the caller's check (T-19-3) before calling.
- Baseline recorded from a freshly created and migrated `invai_t19_2` in the shared tree, not a separate worktree. The mock digest results don't depend on DB content.
