## Acceptance criteria (spec AC numbers in brackets)
1. **Preferences:** per (company, user, kind) with `on`, `source` (`settings | unsubscribe_link | admin`), timestamps; default off (opt-in); an admin can turn someone's email off, never on; RLS + isolation test. [AC23]
2. **sendUserEmail** sends through the existing mailer (Mailpit locally), only when: the user is an active member, email verified, not a PIN-only placeholder, not suppressed, not a sample workspace, preference on, `DIGEST_EMAIL_ENABLED`. Otherwise returns `skipped` with the reason. Idempotent on `dedupeKey` (a second call sends nothing). Deterministic `Message-ID`. [AC2, AC26]
3. **Headers** (RFC 8058): `List-Unsubscribe: <https://…/l/TOKEN>, <mailto:…>` and `List-Unsubscribe-Post: List-Unsubscribe=One-Click`; footer text supplied by the caller includes the postal address from `MAIL_POSTAL_ADDRESS` (placeholder until OI-12).
4. **Signed links:** HMAC tokens bound to company + user + kind + ref, with expiry for clicks (unsubscribe tokens long-lived); tampering with any field (e.g. user in shop B) → rejected and nothing changes in either shop (test). [AC25]
5. **Public routes** (`src/api/links.ts`, no session): `POST /l/:token` for unsubscribe → preference off, source `unsubscribe_link`, idempotent (second POST no change, still 200) [AC24]; `GET /l/:token` for unsubscribe → redirect to the web confirm page, never changes anything (link scanners) [AC24]; `GET /l/:token` for click → dispatch to the registered handler, redirect only to same-origin paths. Rate-limited per IP; no PII in logs.
6. **Env switches** added with safe defaults (`DIGEST_SUMMARY_MODE=shadow`), none in `PRODUCTION_KEYS`.
