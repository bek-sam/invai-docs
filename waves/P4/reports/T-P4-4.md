## Decisions
- `topDesigns`'s only observable output (`id`/`name`/`channel`) can't show a unit-count bug
  without either a ranking flip (ties are unavoidable with this exact ±1-unit fixture, since no
  `ORDER BY` backs the ranking map) or exposing the count. Chose to export the function and add a
  `units` field — safe (structural typing, extra field ignored by all 3 callers) and the most
  direct proof of the fix.
- The cross-listing "sold" query has a `having count(*) >= MIN_UNITS(3)` gate unrelated to this
  bug; used a 3rd supporting unit so the 2-unit reprinted order's effect is observable through the
  gate rather than changing the gate's behavior.
- Neither fixed query selects `revenueCents` (both are pure unit counts used for ranking/gap
  detection, not shown to the user as money), so the card's "both units' revenue" language isn't
  literally testable at these two locations — revenue correctness lives in `getProfit`
  (finance/service.ts, T-P4-1's file, not touched here).
