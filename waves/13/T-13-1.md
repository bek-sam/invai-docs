# T-13-1: Floor API version handshake (B-82)

## Design (r1, product-manager + architect review — see `wave.md` for full rationale)
- Header `X-Contract-Version` on every floor request (`invai-floor/src/api/rpc.ts`), value from a
  new `CONTRACT_VERSION` export in `invai-contracts/src/index.ts`.
- Minimum version lives in **backend** config (`MIN_FLOOR_CONTRACT_VERSION`, `invai-backend/src/lib/env.ts`),
  not in contracts — ops can hold it back during the ADR's grace window without a contracts release.
- Enforced in the `guard` middleware (`invai-backend/src/api/orpc.ts`) for `meta.auth === "floor" || "station"`
  (covers `floor.login` itself). Error: new `CLIENT_TOO_OLD` in contracts `COMMON_ERRORS`, **HTTP 426**,
  `data: { minVersion, current }`.
- New floor `FailureKind` (`"tooOld"`, not retryable) in `src/api/errors.ts` so the outbox never retries it.
- New `ParkReason` `"stale_version"` (`invai-floor/src/outbox/db.ts`): stamp each `OutboxEntry` with the
  contract version it was enqueued under; on replay, a stamped-old entry that the server rejects with any
  4xx parks as `"stale_version"` (lead alert), not the generic `"rejected"`.
- Owns exclusively (batch 1, parallel-safe): `invai-contracts/src/contract/_base.ts` + new `src/compat.ts`;
  `invai-backend/src/api/orpc.ts`, `src/lib/env.ts`, `src/lib/errors.ts`; `invai-floor/src/api/rpc.ts`,
  `src/api/errors.ts`, `src/outbox/db.ts`, `src/outbox/outbox.ts`, its update-needed screen + i18n.
- Lands its contracts version bump + CHANGELOG entry **before** T-13-3 touches contracts (see wave.md
  ownership split) — don't race the same `package.json` line.

## Acceptance criteria
1. **Version header:** every floor request sends `X-Contract-Version` (from the contracts package version). The backend sets a minimum supported floor version.
2. **Old-version request:** it returns a typed `CLIENT_TOO_OLD` error. The floor shows a translated "Update needed" screen with an update button, using the T-4-4 prompt.
3. **Old queued writes:** queued outbox entries recorded on an old version are replayed only if the server still accepts their shape; otherwise they're parked, with a reason and a lead alert. No silent loss.
4. **Compatibility policy:** a documented rule for contract changes that affect the floor (keep old shapes accepted for N days), as a decision record.
5. **Tests:** an old version is refused, a current version passes, and an old outbox entry is replayed or parked.
