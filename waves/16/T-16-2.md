## Acceptance criteria
Each rule below comes from a lesson in `team/lessons.md`. Keep every existing rule and the fail-closed behavior.
1. **Deny `git push` unless the caller is the main session** (no `agent_type`) or `agent_type == "tech-lead"`. Lessons from waves 2 and 8. The message says only the tech lead pushes after the gate.
2. **Deny** in any repo:
   - `git stash` (every subcommand except `list` and `show`);
   - `git reset --hard`, `git checkout -- <path or .>` and `git restore` (without `--staged`) on `.` or a path;
   - `git clean -f`.
   Lessons from waves 4 and 8, and the shared tree.
3. **Deny** `pkill`, `killall`, and `kill` with a pattern (`kill $(pgrep ...)`); plain `kill <pid>` stays allowed. Lesson from wave 2.
4. **Deny** `git add -A`, `git add --all`, `git add .` and `git commit -a`/`-am`. Handbook rule.
5. **Ask** (owner approves) for `pnpm install`, `pnpm i`, `pnpm add` and `npm install`. Lessons from waves 6/7.
6. **Ask** for `db:reset`, unless `agent_type` is `qa-engineer` or the main session. Gates run it.
7. **Adversarial tests:** a table of at least 40 commands (deny, ask, allow) covering env prefixes, `git -C <dir>`, `cd x && ...`, line continuations, `;` and `|`, quoting, uppercase variants where the shell cares, and a malformed input (denied). Allowed cases include `git stash list`, `git restore --staged <file>`, `kill 12345`, `git add src/a.ts` and `git push` from the main session.
