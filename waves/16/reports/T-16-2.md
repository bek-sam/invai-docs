## Built
- `guard-bash.py` keeps every existing rule and the fail-closed input check. It adds the six lesson rules below.
- **Fixed a real fail-open bug.** The old guard exited 1, a non-blocking hook error that lets the call through, in these cases:
  - `command` was not a string (`{"command": 123}`)
  - `tool_input` was a list (`["git …"]`)
  
  Reproduced with the old file: `p1 rc=1`, `p2 rc=1`. Every unexpected error, and any non-string `command` or `agent_type`, now denies.
- **How the new rules read commands.** They work on shell words (`shlex`), not raw text, so a commit message that mentions `git stash` passes (S25, P16). The parser follows:
  - `bash/sh/zsh -c`, `eval`, and `echo … | sh`
  - `$(…)` and backticks, including inside double quotes but not single quotes
  - `(subshells)`, `if/then`, `find -exec`
  - inline `python -c` / `node -e` strings
  - `VAR=value; $VAR` expansion and `${IFS}`
  - prefixes: `env`, `sudo`, `command -p`, `nice -n`, `timeout N`, `xargs [opts]`, `perl -e 'alarm N; exec @ARGV'`, `/usr/bin/…` paths
  - `git` global options (`-C`, `-c`, `--git-dir x`, `--no-pager`)
  
  Command names are matched case-insensitively (macOS resolves `GIT`, `PKILL`, `AWS`); flags stay case-sensitive (`-A` ≠ `-a`). The existing regex rules now also run on a quote-stripped copy of the command and case-insensitively. That only adds denials.
- Also denied, because they defeat the rules: defining git aliases (`git -c alias.x=push x`, `git config alias.sv stash`), ANSI-C escapes (`$'\x67it'`), and nesting shells more than 4 deep.

## Decisions
- Added **`git add -u`**, **`git reset --merge`**, **`git switch -f`**, **`git send-pack`** and **`npm ci`**. They have the same effect as the card's commands (staging everything, discarding the tree, pushing, rewriting `node_modules`).
- **`git checkout <branch>` stays allowed.** `git checkout <file-like path>` (a `/` prefix or suffix, or an extension) is denied, because it discards edits exactly like `-- <path>`. A tag like `v1.2.0` looks like a file and is denied too, which is acceptable.
- **`kill $(lsof -ti :<port>)` stays allowed.** It is the agent brief's own recipe for killing your own server.
- **R5 asks every caller, including the main session**, as the card says. R6 exempts the main session and `qa-engineer`.

## Known gaps (a denylist can't close these; the guard stops mistakes, not a determined bypass)
- Scripts written to a file and then run (`echo 'git stash' > x.sh; bash x.sh` is denied only because the text also appears as a command in the heredoc or echo path, and not in every form)
- `source file`
- shell functions and aliases defined in an earlier call
- base64 or other encoding plus `eval`
- `watch`, `make` or package scripts that run git
- list-form subprocess calls built from variables inside inline code

These are recorded here for security-reviewer to rank.
