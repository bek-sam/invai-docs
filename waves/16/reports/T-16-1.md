## Built
- **`post-edit-check.py`** (PostToolUse `Edit|Write|MultiEdit|NotebookEdit`, timeout 20 s).
  - TS repo or worktree: `biome check --reporter=json <file>` (read-only; no `--write` or `--fix`), then `tsc --noEmit --pretty false` for code files and `tsconfig*.json`.
  - imaging `.py`: `ruff check --no-fix --no-cache`.
  - Feedback reaches the model as `{"decision":"block","reason":…}` for errors, or `additionalContext` for warnings only.
  - Output is at most 40 lines, formatted `file:line:col` first, with errors in the edited file listed first.
  - Tools come from the repo's own `node_modules/.bin` or `.venv/bin`, falling back to the sibling `invai-<kind>` repo (for worktrees). A worktree without `node_modules` gets lint only.
  - If tsc ever takes more than 8 s, it is skipped for 1 h and the model is told to run it itself.
  - Fails open. The difference from the fail-closed guard is written in the docstring.
- **`track-verify.py`** (PostToolUse `Edit|Write|MultiEdit|NotebookEdit` and `Bash`, timeout 5 s).
  - State is kept per `session_id` + `agent_id` (`main` for the main session) in `.claude/state/verify__<session>__<agent>.json`. It is written under `flock`, replaced atomically, and gets a `.gitignore` of `*`. Files older than 2 days are pruned.
  - Edits: records the repo or worktree root, its kind and the edit time. `.md`/`.txt`/image edits and `invai-docs` edits are ignored.
  - Verification commands count only on `PostToolUse`; a failure fires `PostToolUseFailure` instead. A check counts only if it **started** after the edit (`start = now - duration_ms`). Background runs and interrupted runs don't count.
  - Parsing handles: `&&` chains, `cd`, `( … )` subshells, `-C`/`--dir`, `uv --directory`, env prefixes, `perl -e 'alarm N; exec @ARGV'`, `\` line continuations and redirects.
  - Only the trailing `&&` chain counts, since only its success is certain. `a; b`, `a || true` and `a &` don't count `a`.
  - A piped command (`pnpm test | tail`) counts only if the output has no failure markers (`ELIFECYCLE`, `N failed`, `error TS`, `Found N errors`…), or if `pipefail` is set.
  - Filtered or partial runs don't count: `pnpm test src/x`, `vitest -t`, `pytest -k`, `biome check <file>`.
  - Tool must match repo: a python tool never verifies a TS repo, and the reverse.
- **`verify-gate.py`** (Stop + SubagentStop, timeout 10 s).
  - Blocks the first stop while any edited repo lacks a later successful run of its required checks:
    - TS repos: typecheck, lint, test
    - web and floor: also build
    - infra: typecheck, lint (it has no `test` script)
    - imaging: `uv run ruff check .`, `uv run pytest`
  - The message gives `cd <root> && <exact commands>` for each repo. In a worktree it gives the `node_modules/.bin/*` forms, because `pnpm` must not run in worktrees (lesson from waves 6/7). It ends with "If you can't make them pass, stop and report the failure honestly."
  - Stops are allowed when `stop_hook_active` is true, or when the gate already blocked for the same edit state (so a resumed agent isn't blocked again). Fails open.
- **`settings.json`**: registers the three hooks. The PreToolUse guard entry is byte-for-byte unchanged, and a test asserts it.
- **Tests** (`hooks/tests/test_verify_hooks.py`, `test_fast_check.py`): 30 tests covering:
  - each edit type
  - chained, separate, `-C`/`--dir`, subshell and worktree verify forms
  - a failed test run, a piped failure, partial and masked runs
  - a check that started before the edit
  - background runs
  - web build, imaging and infra
  - docs-only edits, read-only agents, per-agent isolation
  - malformed input for all three hooks
  - pruning, atomic writes, concurrent writes
  - the 40-line cap, and that files are never modified (sha256 before and after)
  - docs files under 100 ms, missing tools failing open, and the settings timeout plus the unchanged guard

## Decisions
- **Shared module `invai_hooklib.py`** (repo detection, state, command parser), kept next to the three hooks. `guard-bash.py` doesn't use it, so the guard stays self-contained and fails closed. The card allowed name changes; the tech lead should add this file to the T-16-1 ownership row.
- **Feedback via JSON `decision: block`** for errors (shown to the model as a hook error, so it acts on it) and `additionalContext` for warnings or info only. Both were verified empirically.
- **"Block once" is keyed to the edit state** (`gate_blocked_for`), not only `stop_hook_active`. A resumed agent that already reported a failure isn't blocked again until it edits code again.
- **Worktree commands use `node_modules/.bin/*`**, never `pnpm`, per the lessons from waves 6/7.
- The hooks set `sys.dont_write_bytecode`, so no `__pycache__/` appears in `.claude/hooks/`.

## Known gaps and follow-ups
- Edits made through Bash (`sed -i`, `cat >`, `git apply`, `biome check --write`) aren't tracked as edits. Only Edit, Write, MultiEdit and NotebookEdit are.
- Piped checks rely on output failure markers. `pnpm test | head -3` could hide a failure line. `pipefail`, or no pipe at all, is exact.
- The gate trusts the command text. It doesn't defend against an agent that deliberately fakes a check (for example a shell alias). That is out of scope for a reminder hook.
- A main session started with `--agent X` may carry `agent_type`. That wasn't tested; it doesn't affect the gate, which keys on `agent_id`.
- The fast check runs a full-repo `tsc` on every code edit (0.3–1.4 s). In a shared tree it can report other agents' in-progress errors. These are listed after the edited file's errors, with a note saying where they may come from.

## Blocked by other owners

  - `restore`, line `cp "$B"/hooks/* .claude/hooks/ && chmod +x .claude/hooks/*`: `cp` hits `hooks/tests/`, prints `cp: …/tests is a directory (not copied)`, and the `&&` skips `chmod +x` (reproduced in scratch).

  - Suggested fix:
    - restore: `cp "$B"/hooks/*.py .claude/hooks/ && chmod +x .claude/hooks/*.py`
    - backup: `mkdir -p "$B/hooks" && cp .claude/hooks/*.py "$B/hooks/"`, keeping the existing `hooks/tests/`.
