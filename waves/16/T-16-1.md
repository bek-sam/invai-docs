## Acceptance criteria
1. **Fast check (PostToolUse, Edit|Write|MultiEdit):**
   - For a `.ts/.tsx/.js/.json` file inside a TS repo, or a worktree of one: run that repo's Biome on the file only, read-only (never `--write`).
   - For a `.py` file in invai-imaging: `ruff check <file>`.
   - Also run the repo's typecheck when it takes under 8 s. Measure every repo and put the times in the report.
   - Errors reach the model: at most 40 lines, file:line first.
   - Any other file (docs, md) exits 0 in under 100 ms.
2. **Fails open, fast:** a crash or timeout in the fast check never blocks an edit. The hook's own `timeout` is ≤ 20 s. The difference from the guard, which fails closed, is written in a comment.
3. **Tracker:** records per `session_id` + `agent_id` (or `main`):
   - which code repos (or worktrees) were edited, and when;
   - which verification commands succeeded afterwards and in which repo (`pnpm typecheck`, `pnpm lint`, `pnpm test` — also `node_modules/.bin/*` forms, `vitest run`, `tsc`, `biome check`; imaging `uv run ruff check .` and `uv run pytest`; web/floor `pnpm build`). Chained commands (`&&`) and `cd <repo> &&` / `-C` / `--dir` forms count.
   - State lives in `.claude/state/` (git-ignored), files older than 2 days are pruned, and writes are atomic.
4. **Gate (Stop + SubagentStop):**
   - If any repo was edited after its last successful typecheck, lint and test, block the stop once. The message names the repo and the exact commands, and says: "If you can't make them pass, stop and report the failure honestly."
   - With `stop_hook_active` true, allow the stop.
   - Read-only agents and docs-only edits never block.
   - A web/floor repo also needs `pnpm build`.
5. **No false blocks:** the main session editing only `invai-docs/**` is never blocked. An agent that ran all checks after its last edit is never blocked.
6. **Tests:** `python3 -m pytest invai-docs/team/hooks/tests` (or plain `unittest`) feeds JSON fixtures to each hook: each edit type, a chained verify command, a failed test run (not counted), stop with and without checks, `stop_hook_active`, a worktree path, a malformed input.
7. `settings.json` registers the new hooks and keeps the existing PreToolUse guard unchanged.
