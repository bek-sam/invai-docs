## Decisions
- Template clone (`CREATE DATABASE ... TEMPLATE`) over re-running migrations per run: faster, and
  avoids the "two runs race on CREATE EXTENSION" issue `db/migrate.ts` already documents.
- One outer advisory lock scoped to a `/postgres` connection serializes ensure-template +
  stale-sweep + clone end-to-end (not just the migration), because Postgres refuses
  `CREATE DATABASE ... TEMPLATE` outright if any other session is connected to the template —
  retrying past that isn't an option, so the whole section had to be one lock.
- Redis registry lives in DB 15 (now reserved, never a test target) rather than DB 0, so claiming
  a DB never touches the dev/CI worker's DB.
- `provide()`/`inject()` chosen over relying on `process.env` propagation into forked/threaded
  workers, per the card's explicit instruction to verify the real Vitest 5 API rather than assume.
- `vi.useFakeTimers()` was tried first for the market http.test.ts fix and reproducibly hung
  `takeToken`'s real Redis round trip even restricted to `toFake: ["setTimeout","clearTimeout"]`
  (confirmed with a standalone repro); stubbing only `global.setTimeout` to run immediately
  sidesteps it (ioredis/pg hold a module-load-time reference to the real `setTimeout`).
