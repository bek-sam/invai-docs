# T-12-4 Tenant export, deletion and retention

Backlog B-23 (S-G11, S-G13), without AWS KMS. **Runs in parallel with T-12-2 and T-12-3, after T-12-1 lands; the most isolated of the four cards** (see `wave.md`, "Ownership split" and stub B for the exact contract). Owned files: `src/modules/privacy/service.ts`, new `src/modules/privacy/jobs.ts`, new `src/modules/privacy/router.ts`, new `invai-contracts/src/contract/privacy.ts`. Coordinate on: `src/lib/s3.ts` (additive bulk-delete helper), `src/db/schema/tenancy.ts` (adds `"tenant_export"` to `JOB_KINDS`, additive), `src/api/router.ts` (one-line registration).

New permissions `org.export` and `org.delete` in `invai-contracts/src/roles.ts`, granted to the `owner` role only (carved out of `admin`'s `SHOP_ALL`, the same way `billing.manage` already is) — this is a company-owner action, never a bare `admin`.

## Acceptance criteria (each item has its own test)

1. **Export trigger and status**, exactly the `privacy.exportTrigger`/`exportStatus` shape in `wave.md` stub B. Reuses the existing `jobs` + `files` + `files.downloadUrl` pattern (no new download endpoint): the job zips one JSON+CSV pair per tenant table plus the company's uploaded files, uploads via `lib/s3.ts`, creates a `files` row, and records that file id in `jobs.resultIds`. Test: trigger an export on a seeded company, wait for `status: "done"`, call `files.downloadUrl` with the returned file id, and assert the downloaded zip actually contains a CSV for at least one non-trivial table (e.g. `orders`) with the right row count.
2. **Only one export at a time per company.** A second `exportTrigger` while one is `queued`/`running` throws `EXPORT_IN_PROGRESS` with the running job's id — test both the happy path and this conflict.
3. **Deletion: soft-delete then 30-day hard purge**, the `deleteRequest`/`deleteCancel`/`deleteStatus` shape in stub B. `deleteRequest` sets a `deletedAt` and schedules an idempotent `tenantHardPurge` job (jobId `hard-purge:{companyId}`) 30 days out; `deleteCancel` works only before the purge has run. Test: request deletion, assert `deleteStatus` reports `soft_deleted` and a `scheduledPurgeAt` ~30 days out; cancel; assert `deleteStatus` returns to `active` and the delayed job no longer fires (run it inline in the test and assert it's a no-op, not an error, since it may already be unscheduled).
4. **Hard purge actually purges**, including S3 objects. Test: run `tenantHardPurge` inline (fast-forwarded) against a seeded company with at least one uploaded file, then assert (a) the company's tenant rows across a representative sample of tables are gone or anonymized per the audit design, and (b) the S3 objects for that company's files are gone from the (MinIO-backed) bucket — check via a `HeadObject`/list call, not just that the DB row is gone.
5. **Audited.** Every one of `tenant.export_requested`, `tenant.delete_requested`, `tenant.delete_cancelled`, `tenant.purged` writes an `audit_log` row with the acting user id (export/delete requests) or `system` (the purge). Test: one assertion per action.
6. **Buyer-PII retention at 18 months.** A `reports` sweep redacts buyer PII on orders older than 18 months, independent of the export/delete flow. Test: seed an order at 18 months + 1 day old, run the sweep, assert the PII fields are gone/redacted and non-PII fields (totals, item counts) are untouched.
7. **`floor_requests` retention purge** (wave 4 follow-up, folded in here): a `reports` sweep deletes `floor_requests` rows older than 30 days. Test: seed an old row and a recent one, run the sweep, assert only the old one is gone.
8. **Cross-tenant safety, required** for every item above: run each against two seeded companies and assert company B's rows, files and audit log are untouched by an operation on company A — use the RLS test-harness pattern (`db/rls-coverage.test.ts`), not a mock, since this is exactly the class of bug RLS is meant to catch.

## Explicitly out of scope (flagged in `wave.md`)
No AWS KMS (per the card's own scope). Object storage work runs against the existing MinIO-backed `lib/s3.ts` — no new AWS dependency this wave.
