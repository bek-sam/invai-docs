# T-12-5 CSP and security headers

Backlog B-24 (S-G5, S-G6). Owned by web-engineer + floor-engineer, not backend-foundation — no ownership-split conflict with T-12-1..4. It touches the API's header middleware (`src/api/app.ts`) only additively (new response headers, not new routes); coordinate with T-12-2 if both land the same week, since T-12-2 also edits `app.ts` (additive `/livez`/`/readyz`) — different lines, low risk.

## Acceptance criteria (each item has its own test)

1. **Strict CSP with a nonce or hash** — not `'unsafe-inline'` — for `invai-web` and `invai-floor`, in both the Vite dev server (dev-time CSP or an equivalent dev proxy header) and the prod build's headers config. Test: a real browser run of the golden path (per the card) with zero CSP violations in the console; additionally, a static check that the built HTML/JS contains no inline `<script>`/`onclick=` that would require `'unsafe-inline'`.
2. **HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy`, `Permissions-Policy`** present on every response from web, floor and the API. Test: an automated headers check (e.g. a small script hitting each app's root and the API's `/health`) asserting each header's exact value, not just presence — a wrong value (e.g. HSTS without `includeSubDomains` where the design calls for it) should fail the test.
3. **Uploaded SVGs never served inline.** Files with SVG content-type are served either as `Content-Disposition: attachment` or are sanitized before being served inline (strip `<script>`, event handlers, external refs). Test: upload an SVG containing a `<script>` tag through the existing files flow, fetch it back, and assert either the response is forced to download (attachment) or the returned bytes no longer contain the script — pick one strategy and test that one, not both loosely.
4. **The API sets the same header set** as web/floor (not just the SPAs) — test the API's own responses (JSON endpoints included), since a strict CSP without a matching `X-Content-Type-Options`/`Referrer-Policy` on the API is a common gap.
5. **No CSP violations in a real browser golden-path run** (not just a lint of the header string) — required evidence in the task report, with the console output attached or quoted.

## Explicitly out of scope (flagged in `wave.md`)
No AWS/CDN dependency: headers are set by the app itself. Confirm during review that nothing here assumes a future CloudFront/ALB header policy.
