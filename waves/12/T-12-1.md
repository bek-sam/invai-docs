## Acceptance criteria (each item has its own test)

1. **Jitter per job type.** `DEFAULT_JOB_OPTIONS` (or a per-`defineJob` override) uses `backoff: { type: "exponential", delay, jitter: 0.5 }`. Test: enqueue the same job type 20 times with a forced failure and assert the observed retry delays are not identical (jitter is actually applied, not just accepted by the type).
2. **`UnrecoverableError` for permanent failures.** A documented helper (e.g. `permanentFailure(reason)`) throws BullMQ's `UnrecoverableError`. Test: a job whose input is Zod-invalid, or that receives a 4xx from a provider mock, is marked `failed` after **1** attempt, not 5 — assert `job.attemptsMade === 1` at the terminal state.
3. **DLQ + alert + redrive**, exactly as designed in `wave.md` stub A (`/internal/dlq/failed`, `/internal/dlq/redrive`, `/internal/dlq/redrive-outbox`, gated by `X-Internal-Token` vs `env.INTERNAL_ADMIN_TOKEN`). Tests:
   - A request without the header (or wrong token) gets 404, never a partial response.
   - `redrive` on a real failed job id causes it to run again and reach `completed`; on an unknown id it's returned in `notFound`, not thrown.
   - A queue whose failed-count grows past N in 15 minutes raises alert kind `queue_failed_spike` exactly once per spike (not once per failed job).
4. **Outbox purge + parked-event alert.** Dispatched outbox rows older than 7 days are deleted in batches by a `reports` job. Rows with `attempts >= MAX_ATTEMPTS` raise alert kind `outbox_parked`; the alert does not re-fire every sweep tick for the same still-parked row (dedupe key = event id). Test: seed a parked row, run the sweep twice, assert exactly one alert.
5. **Stuck sweeps** for the generic `jobs` table (`db/schema/tenancy.ts`, all `JOB_KINDS`) and `ai_jobs`: a row stuck `queued`/`running` past a threshold with no live BullMQ job backing it is marked `failed` with an error and triggers the same realtime `job.progress` event `worker/job-failures.ts` already sends on final failure. Test: insert a `jobs` row with `status: "running"` and an old `updatedAt`, no matching job in Redis; run the sweep; assert it flips to `failed`.
6. **Buy/void/push intents**: confirm (don't rebuild) `shipping/jobs.ts`'s existing `stuckIntentSweepJob` covers all three intent kinds; add a test asserting each of `buy`/`void`/`push` reaches `alertStuck` after its retry budget, if one is missing today.
7. **Webhook deliveries**: rows stuck at `received` past N minutes (enqueue failed, then the process crashed) are flagged — extend `channels/jobs.ts`'s existing purge job or add a sibling sweep. Test: a `webhook_deliveries` row at `received` older than the threshold produces one alert and is not silently purged before it's flagged.
8. **Outbox jobId fix** (T-3-4 review: the relay overrides every subscriber's own `jobId`/idempotency key with `${eventId}:${jobName}`). Fix: prefer the subscribed job's own `def.jobId(input)` when one is defined, falling back to `${eventId}:${jobName}` only when it isn't. Test: a job definition with a custom `jobId` (e.g. the scrap-hash id) that is subscribed to two different outbox events with the same payload enqueues **one** BullMQ job, not two — assert on `queues[q].getJob(expectedId)`.
9. **AI spend-breaker fail-open alert** (wave 8 T-8-2 follow-up, folded in here): a Valkey failure that opens the breaker raises alert kind `ai_breaker_fail_open` in addition to the existing log line. Test: force the Valkey call to reject and assert one alert row is created.
