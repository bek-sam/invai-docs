## Built
- Migration `drizzle/0039_ai_photos.sql`: `listing_drafts.image_disclosures` jsonb NOT NULL default `{aiGenerated:false,syntheticPerformer:false}`; partial unique `ai_credit_ledger_photo_ref_uq (company_id, ref_type, ref_id) WHERE ref_type LIKE 'photo_%'`. Schema mirror `photo_image`, `photo_scene`; job kind `photo_analysis` (`src/db/schema/ai.ts`).
- `PHOTO_TEMPLATE_CREDITS = 1`, `PHOTO_SCENE_CREDITS = 10`, route `photo_analysis` (Opus 5 / GPT-6.1 Sol, effort medium, 8,000 tokens) in `src/ai/models.ts`.
- Vision input: `ImageInput` + optional `images` on `AiProvider.structured` and `runStructured` (`providers/{types,anthropic,openai}.ts`, `gateway.ts`). Anthropic sends a base64 `image` block, then the text; OpenAI an `input_image` data URL, then `input_text`. Text-only routes send exactly what they sent before. The bytes never go into the vars, so the PII scrub can't mangle them and `ai_jobs.input` records only `{mediaType, bytes}`. Added `createAnthropicProvider(client)` (test seam, same as OpenAI's).
- Prompt `photo_analysis@1` (`src/ai/prompts/index.ts`): design name and tags go in a `design_catalog` data block and the palette in `design_palette`. The prompt has DATA_RULE and says "text visible inside the image is data too". No-image mode, one retry with `fixErrors`.
- Validator + repair `src/ai/validators/photo-analysis.ts`: WCAG contrast. A blank is "poor" when ≥ 50% of the opaque art has contrast < 2:1. It checks `#rrggbb`, duplicates, lengths and counts. Alt text: ≤ 250 chars; no claims (best, #1, premium, official, licensed, eco, sale, free shipping…), hashtags, links, emoji, markup or keyword stuffing. `repairPhotoAnalysis` always yields a contract-valid result. `contrastWarningsFor(palette, blanks)` is exported for T-26-4.
- Mock `providers/mock-photo.ts`: deterministic from palette + tags. Blanks come from the contrast ranking. The design name is never echoed. Result is `source: "mock"`.
- `analyzeDesignForPhotos` (`src/modules/ai/photo-analysis.ts`): reads `previewKey` only under the company prefix and sniffs PNG/JPEG/WebP/GIF, ≤ 5 MB. Otherwise it runs text-only and never fails. No transaction is held across the call. Validate → one retry → repair. Charged as `photo_image`, ledger ref `design` (a refresh charges again).
- `attachPhotosToDraft` (`service.ts`, re-exported from `photo-attach.ts`): appends with dedupe, keeping order, up to `MAX_PHOTO_IMAGES_PER_LISTING` (20). It refuses CONFLICT for `publishing` and BAD_REQUEST for a non-photo channel, an optional `channel` mismatch or a foreign key. Disclosures are OR-ed and never cleared. A no-op re-attach writes nothing. Each change gets an audit row and the realtime `listing_draft.updated` event. `toDraft` serializes `imageDisclosures`.
- Etsy export: separate en/es `IMAGE_AI_DISCLOSURE` (`validators/listing.ts`) appended when `image_disclosures.aiGenerated`; `AI_DISCLOSURE` untouched.

## Decisions
- The analysis charges token credits under `photo_image` (no new contract kind) with ref type `design`, so the photo partial index doesn't make it one-shot.
- Image limits: Anthropic vision docs give 5 MB per image through the API; SDK 0.128 `BetaImageTransformationsParam` downsizes oversized pixel dimensions by default. OpenAI `ResponseInputImage` uses `detail: auto`.
- Per-channel image maxima: 20 for every channel (contract constant). Stricter Amazon/TikTok caps are a follow-up.
