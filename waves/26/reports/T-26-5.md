## Known gaps / QA spec (not mine to fix, `e2e/listing-photos.spec.ts`)
1. `getByRole("checkbox", {name:"White"})` strict-mode-violates against the "On model (white)" view checkbox (Playwright's default name match is substring, case-insensitive) — structural, not data-dependent; needs `exact: true` on the color checkboxes.
2. `getByText(/don't have access|no access|not authorized/i)` strict-mode-violates: the shared `ErrorState` always renders both "No access" and "You don't have access…" — same pair every FORBIDDEN screen in the app shows; needs `.first()`.
3. Test 2 ("unapproved image…") failed only because my own manual exercising above left the demo set's images already approved; passes on a fresh seed.
I did not edit `e2e/**`; reported here per the card.

## Decisions
- Colors deduped by name, not hex, so two blank styles sharing a color name render one checkbox (found via #1 above before I fixed it).
- Zip auto-exports on any approved-count change (no manual "Export" button) — matches the spec's implicit flow and the QA script's expectations.
- Fill/longest-px numbers for check messages are a local display-only mirror of `invai-imaging/app/photos.py` PRESETS (backend's `PhotoCheckFailure.detail` is null in phase A); flagged in code comments.
