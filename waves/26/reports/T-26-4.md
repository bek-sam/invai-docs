Slots per channel follow the analysis `imageOrder`; amazon slot 0 = `amazon_main`.
- Jobs (`jobs.ts`): `photos.dispatchSet` (on `photo_set.created`) → one `photos.renderComposition` per composition on `render` at `BULK_PRIORITY` (below sheet builds' default 0). Three steps: claim images, render via imaging (real `widthIn/heightIn`, chosen hex, key `<company>/photos/<set>/<image>.jpg`), then lock set → composition `FOR UPDATE`, record results, charge once when `charged_at IS NULL` (ledger kind `photo_image`, ref `photo_composition`), lead image carries the credit. Transient imaging error retries; on the last attempt or a 4xx the image is `failed` with readable text; set ends `ready` (failures counted) or `failed`; `photo_set.completed` emitted once; `photo_set.updated` published.
- `reviewImages` (transitions from contract; `not_reviewable`, `image_not_in_set` with counts), `exportZip` (approved only, `not_approved` count, fingerprint reuse, `photos.buildZip` job, names `<channel>/<slot>-<garment>-<view>-<color>.jpg`), `attachToDraft` (ai `getDraft` → NOT_FOUND; excludes unapproved/channel mismatch; flags false/false for templates), `listSets` (signs only the lead image), `getSet` (presigns only `isCompanyKey` keys).
