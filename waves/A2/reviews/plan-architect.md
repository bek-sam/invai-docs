2. Storage: **precomputed by a daily job into a table; the read is a SELECT.** Reason: one build runs the snapshot plus five analytics services over months of orders (rule 9), Today is the most-loaded screen, the window (7 days ending yesterday) is fixed for the whole day, and a stored set gives `recordActionClick` a row to validate `key` against. Shape for T-A9: `today_actions (company_id, date, key, rank, detector, kind, params, href, impact_cents, generated_at)`, unique `(company_id, date, key)`; `today_action_clicks (company_id, date, key, user_id, clicked_at)`, unique `(company_id, date, key, user_id)` with a composite FK to `today_actions` (first click per caller, like `digest_clicks`). Hourly `reports` sweep builds any shop whose local date has no set; jobId `today-actions-${companyId}-${date}`; rebuild = delete+insert in one tx. Retention 90 days. Contract consequence: `generatedAt: Timestamp.nullable()`; null means "not built yet" (read enqueues the build, returns `actions: []`, `steady: false`; the web hides the panel). Unknown `key` → domain error `ACTION_NOT_FOUND` (404).

The rows of every grouping are orders (`finance-service.ts:423-428`), so counting orders is the consistent unit; the field name stays (a rename is breaking).
