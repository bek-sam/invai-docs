## Built
- **Domain and HTTPS (B-03, B-57).** The deploy variable `INVAI_DOMAIN` sets one registrable domain; the config validates it and refuses to run without it.
  - Hosts are `app|floor|api.<domain>` in production and `app|floor|api.<stage>.<domain>` on other stages.
  - The API ALB has an ACM certificate (`sst.aws.dns()`), HTTPS on 443 with `ELBSecurityPolicy-TLS13-1-2-2021-06`, and HTTP 80 redirecting to 443. It also sets `dropInvalidHeaderFields`.
  - The static sites get their domains through the same variable. (files: invai-infra/sst.config.ts)
- **Imaging URL (B-57).** Imaging is reached by its Cloud Map name, `http://${imaging.service}:8000`. The old `imaging.url` throws `VisibleError` for a service with no public port (service.ts `get url`), so it was a deploy-time failure.
- **Worker env (B-57).** Api and worker share `BETTER_AUTH_URL`, `WEB_ORIGIN`, `FLOOR_ORIGIN`, `IMAGING_URL`, `NODE_ENV=production` and the S3 settings.
- **Commands.** They now use the agreed entry points: `dist/api/server.js`, `dist/worker/index.js` (it was `dist/index.js`), and the three CLIs.
- **Imaging S3 config.** Imaging gets `S3_ENDPOINT`, `S3_ACCESS_KEY_ID` and `S3_SECRET_ACCESS_KEY` set to `""`, which `or None` turns into boto3's default chain, i.e. the task role. It also gets `S3_CREATE_BUCKET=false`, `S3_REGION`, `IMAGING_ENV=production` and `IMAGING_DEV_ENDPOINTS=false`.
- **`IMAGING_SHARED_SECRET`** goes to api, worker and imaging.
- **Graceful drain.** `stopTimeout` is 45 s on every container, through a `taskDefinition` transform. ALB target deregistration is 30 s (the default was 300 s). Health checks use `/readyz` (10 s interval, 2 healthy / 3 unhealthy). The ECS circuit breaker with rollback is the component default and is verified as on.
- **Valkey (B-02).** `cluster: false` (the component default was cluster mode on), `maxmemory-policy noeviction`, and `t4g.micro` / `t4g.small` by stage.
  - Found and fixed: SST's generated AUTH token can contain `#&$^<>-`. A raw `#` in `rediss://default:<token>@…` cuts off the URL, so the token is now percent-encoded (ioredis `parseURL` decodes it).
- **RDS (B-74, B-01).**
  - Instance `t4g.small` (staging) or `t4g.medium` (production); storage 20 or 100 GB.
  - Backups 14 days, 35 in production (the component default was 7).
  - `deletionProtection` and a named final snapshot in production (the component default was `skipFinalSnapshot: true`); `copyTagsToSnapshot`, and CA `rds-ca-rsa2048-g1`.
  - `rds.force_ssl=1` (the component default was 0).
  - Api and worker connect as **`invai_app`**, through RDS Proxy in production using a proxy credential for `invai_app`, and directly on other stages.
  - The owner role URL points directly at the instance and is used for migrations, the relay and cross-tenant jobs.
  - Both URLs use `sslmode=verify-full`. pg-connection-string 2.14 treats `require` as `verify-full` anyway, so this spells out what already happens.
- **S3 (B-73).**
  - Versioned. The only lifecycle rule is bucket-wide: noncurrent versions expire after 7 days, incomplete multipart uploads abort after 1 day, and expired delete markers are removed.
  - The old `sheets/` and `raw/` prefix rules never matched anything, because real keys are `{companyId}/{kind}/…` (backend `src/lib/s3.ts` `objectKey`). Per-kind retention is the app's purge job.
  - CORS was the component default `*` (every origin, every method). It is now GET/HEAD/PUT from the stage's web and floor origins only.
  - `forceDestroy` is off in production.
- **Secrets (B-77).** Every `PRODUCTION_KEYS` entry is an `sst.Secret`, plus the core secrets (table below).
  - Values reach containers only through **SSM SecureString** parameters `/invai/<stage>/<ENV>` via the `ssm` prop, never through the environment in the task definition.
  - Secrets and the DB are no longer `link`ed. A link wrote the value in plaintext as `SST_RESOURCE_*` env, including the RDS master password.
  - `MAIL_FROM` is derived from the domain.
  - `ALLOW_MOCKS=true` only when the stage is `demo`. Only there do provider keys get a `" "` placeholder, which env.ts trims to unset; SSM rejects an empty value.
- **KMS.** Key and alias `alias/invai-<stage>-field-encryption`. It is passed as `FIELD_ENCRYPTION_KMS_KEY_ID` (the ARN) with `FIELD_ENCRYPTION_PROVIDER=kms`. Api, worker and migrate may call `kms:Encrypt`, `kms:Decrypt` and `kms:GenerateDataKey` on that key only.
- **SES.** `sst.aws.Email` sets up the sender (`<domain>` in production, `<stage>.<domain>` elsewhere) with DKIM, DMARC (`p=quarantine`, strict alignment) and a `mail.` MAIL FROM. This replaces the placeholder `*.invai.example` identity.
- **Migrate task (B-59, AC4).** `sst.aws.Task("Migrate")` runs `sh -c "node dist/db/bootstrap-cli.js && node dist/db/migrate-cli.js && node dist/db/reference-seed-cli.js"` with the backend env and SSM secrets. It has the owner URL as `MIGRATION_DATABASE_URL` and the `invai_app` URL as `DATABASE_URL`.
  - `infra/run-migrate.ts` (sst SDK `task.run` / `task.describe`) starts the task, polls it, and exits with the container's result. The timeout is 20 min.
  - `pnpm deploy:staging|prod` now runs three steps: deploy `--target Migrate`, then `release:migrate:<stage>`, then the full deploy. A failed migration stops the rollout. (files: invai-infra/infra/run-migrate.ts, package.json)
- **Network and cost (B-107).**
  - ECS tasks moved to the **private subnets** with no public IP; the SST default was the public subnets with a public IP. The ALB stays in the public subnets.
  - An S3 gateway endpoint serves the private route tables.
  - All tasks are ARM64.
  - Api scales on CPU 60% plus 1,000 requests per target; imaging scales on CPU 70% (max 3 in production).
- **WAF (production).** A REGIONAL ACL is associated with the ALB. A CLOUDFRONT ACL (us-east-1 provider) is set on both distributions through `transform.cdn.webAclArn`.
  - Rules: a per-IP rate rule (20,000 per 5 min on the API, 5,000 on CloudFront) with `/webhooks/` exempt, plus AWS IP reputation, common rules and known-bad-inputs.
  - `SizeRestrictions_BODY` and `CrossSiteScripting_BODY` only count, not block (webhook bodies are over 8 KB; listing HTML).
- **CloudFront security headers.** CloudFront sent no CSP at all before, because the CSP lived only in `vite preview` and nginx. A viewer-response function now adds CSP, HSTS, nosniff, Referrer-Policy and Permissions-Policy.
  - `connect-src` comes from the web and floor `csp.ts` helpers, imported by the config.
  - Web's `connect-src` includes `https://<bucket>.s3.<region>.amazonaws.com`. The backend presigns on that host because the config sets `S3_FORCE_PATH_STYLE=false` and `S3_PUBLIC_ENDPOINT=https://s3.<region>.amazonaws.com`.
- **B-190 web hunk.** `csp.ts` has a new `uploadOrigin(VITE_S3_ORIGIN)`: one https origin, `http://localhost` allowed, wildcards and plain http refused, and unset means no extra origin. `connectSrc(api, s3 = "")` adds it. `vite preview` defaults to local MinIO, which fixes wave 20 gate issue 1. (files: invai-web/src/lib/build/csp.ts, vite.config.ts)
- **README** "AWS (SST)" is rewritten: what is created, the owner-input table and the release order.

## Decisions
- **Domain from an env variable (`INVAI_DOMAIN`), not an `sst.Secret`.** It isn't secret, secret outputs are masked in stage outputs, and a missing value fails at synth with a clear message.
- **SSM SecureString for every secret instead of `environment`/`link`.** Neither SST path keeps the value out of the task definition. The execution role already has `ssm:GetParameters` (fargate.ts `createExecutionRole`).
- **Tasks in private subnets.** This fits "data stores and services private" and research 11's NAT-instance design. The cost is that the NAT instance is now on the egress path (a single point of failure; see gaps).
- **`sslmode=verify-full` + `NODE_EXTRA_CA_CERTS`, not a Pool code change.** It adds the RDS CA without replacing Node's roots, so direct connections (RDS CA) and the proxy (Amazon public CA) both verify.
- **Bucket-wide lifecycle, not per-prefix.** Prefix rules can't select `{companyId}/{kind}`.
- No cross-cutting ADR written. These are ops choices within the card; the tech lead may want an ops decision for "secrets via SSM only" (proposed).
