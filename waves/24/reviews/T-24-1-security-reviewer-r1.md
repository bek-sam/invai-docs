## Blocking findings
1. **`invai-infra/sst.config.ts` (no `transform.executionRole` on `Api`, `Worker`, `Imaging`, `Migrate`) — every ECS task's execution role can read every SSM parameter and Secrets Manager secret in the AWS account, not just its own stage's.** `.sst/platform/src/components/aws/fargate.ts:1040-1050` grants `ssm:GetParameters/GetParameter/GetParameterHistory` and `secretsmanager:GetSecretValue` on `resources: ["*"]` to every Fargate execution role by default, and nothing in this diff narrows it. This diff is what makes that wildcard load-bearing: it moves every production secret — including `MIGRATION_DATABASE_URL`, the **unrestricted owner-role Postgres URL** used for cross-tenant jobs, which bypasses RLS entirely — into SSM SecureString params at `/invai/<stage>/<ENV>`, delivered to containers via the `ssm` prop. SecureString here uses the default AWS-managed key (no `keyId` set), so `ssm:GetParameter` alone decrypts it; no extra KMS grant gate exists. Concrete failure scenario: a task in `demo` or `staging` (lower-trust stages sharing this account) is compromised — via a dependency RCE, or SSRF into `Imaging`, which has no request auth — and the attacker calls `ssm get-parameter --name /invai/production/MIGRATION_DATABASE_URL --with-decryption` directly against the AWS API. That single read gives full, RLS-bypassing read/write access to every tenant's `buyer_pii` in production, from a task that has no legitimate reason to ever touch production data. This is exactly the class of exposure this security review program exists to catch (research 11 §7.1 "SST defaults bite"; v1-review.md's own Amazon-readiness item 9 calls for "least-privilege IAM per service"), and the card explicitly asked co-reviewers to check IAM scope. Fix: add `transform.executionRole` on each of the four compute resources (or one shared helper, the same pattern already used in this diff for `transform.taskDefinition`/`transform.parameterGroup`/`transform.instance`) narrowing the two statements' `resources` to `arn:aws:ssm:${region}:${accountId}:parameter/invai/${stage}/*`, and dropping or equally scoping `secretsmanager:GetSecretValue` if Secrets Manager stays unused. Recorded as **S-45** (Medium — needs a second condition, an initial task compromise, per this file's own severity legend) in `invai-docs/security/v1-review.md`, owner platform-sre, due inside the 30-day High-adjacent clock given the blast radius reaches cross-tenant PII once triggered; not blocked from fixing before the card's first real deploy, since nothing has been deployed yet.
