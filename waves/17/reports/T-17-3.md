## Decisions
- The tool line goes at the start of the assistant turn's text, not in a separate message. The API needs alternating roles, and this keeps the 20-message window and the gateway's history scrub unchanged. Summaries come from our tools, not from the model or the user. Bracket and angle-bracket stripping still stops a summary built from shop data from faking the line end or a tag.
- The shop context is labelled "set by InvAI, not by the user", and only derived values go in it (IANA zone validated by `Intl`, channel labels from `CHANNEL_RULES`). Free text such as connection names never goes in.
- `ai_jobs.input.prompt` now carries `assistant@4` so cost and quality can be split by prompt version (role rule: log prompt id and version).

### S-33: fixed pending verification (security-reviewer to verify; `v1-review.md` not edited)
- `assistantTools` wrapper (invai-backend/src/modules/ai/assistant-tools.ts `rangeProblem`, `MAX_RANGE_DAYS = 400`): every tool whose input has `from`/`to` (and `previousFrom`/`previousTo` on compare_periods) checks the span before any query. A bad range comes back as a normal tool result: `data: {error: "invalid_range", message, maxDays: 400}`, `answer` = the message, for example "Range too long (from/to); max 400 days. Ask for a shorter period or split it." The same goes for `from >= to` ("the start must be before the end") and unparseable dates.
- Why a result and not a throw: `BetaToolRunner` (node_modules/@anthropic-ai/sdk/lib/tools/BetaToolRunner.js:644) would turn a throw into an `is_error` tool_result the model can read. But our provider pushes the `tool_call` event before running the tool, so a throw leaves the UI chip with no `tool_result`. The mock also calls tools directly, so a throw would end the whole answer. A normal result works on both paths.
- Tests (assistant-tools.test.ts "S-33: range span cap"): a 1900–2026 range is refused on all 8 ranged tools (get_profit, get_orders_summary, get_listing_performance, get_channel_performance and the four analyst tools). Also refused: from after to, a bad date and an oversized previous period. Exactly 400 days is allowed. The earlier "throws on from > to" test now expects the recoverable result.
