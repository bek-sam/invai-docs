## Decisions
- **Minor bump (0.4.0 -> 0.5.0), not patch.** No T-13-2 version-check script exists (checked:
  `invai-docs/waves/13/T-13-2.md` has no matching report in `invai-docs/waves/13/reports/`, no
  `check:consumers` script in `invai-contracts/package.json`, no CI step in
  `invai-contracts/.github/workflows/ci.yml` for it) - it was planned but never built. Decided by
  hand: every prior CHANGELOG entry (0.3.0 additive, 0.4.0 with a removal) bumped minor while the
  package sits at 0.x, matching the README rule "bump the minor version on 0.x," and standard
  semver treats a backward-compatible enum addition as a feature (MINOR), never a fix (PATCH). Not
  cross-cutting enough to need a new ADR (it's the ordinary "add an enum value" case the
  `add-contract-procedure` playbook already covers); recorded in the CHANGELOG instead.
- Put the new enum values at the end, in the exact order the card lists them, per the additive
  rule and to keep `get_production_status` (already an implemented backend tool) first among the
  new entries.
- Left `FLOOR_COMPAT_BASELINE` untouched: `AssistantEvent` has no floor consumer.
