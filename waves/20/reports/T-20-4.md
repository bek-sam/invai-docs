## Built
- New `guard-paths.py`, a PreToolUse hook for the file tools (files: `invai-docs/team/hooks/guard-paths.py`):
  - **tech-lead** may write only: `invai-docs/{waves,team,research,decisions}/**` (except any `reviews/` folder under `waves/`), `invai-docs/owner-inbox.md`, the root `CLAUDE.md`, `.claude/{agents,skills}/**`, `.claude/agent-memory/tech-lead/**` and `invai-docs/.claude/agent-memory/tech-lead/**`.
  - **reviewer** may write only: `invai-docs/waves/<n>/reviews/**` and `.claude/agent-memory/reviewer/**`.
  - **Path handling:** paths are resolved before the check. Relative paths resolve against the hook's `cwd`; `..` and symlinks are followed with `realpath`; case is folded (macOS). A hard link (`nlink > 1`) is denied. `~` paths are denied.
  - **Workspace root:** `CLAUDE_PROJECT_DIR`, or its nearest parent that holds `invai-docs/`, so a session started in `invai-docs` still works.
  - **Failure handling:** restricted agents fail closed (bad input, no path, no workspace, or an internal error all give exit 2). Other roles pass untouched.
  - **Missing agent_type:** the call is allowed, and one line (time, `main` or `no-agent-type agent_id=…`, tool, path; never content) goes to `invai-docs/team/state/guard-paths.log`. That folder gets its own `.gitignore` (`*`), and the log rotates at 512 KB.
- `guard-bash.py` (B-116):
  - **Push, regex layer:** the push regex no longer runs on the whole joined line. It runs per segment, split on `&& || | |& & ; newline ( ) backtick $(`.
  - **Push, word layer (new):** `_push_is_dangerous` checks the push's own shell words, so bash -c, eval, `$(...)`, pipes into a shell and `VAR=` expansion are all covered. It denies:
    - short flags containing `f` or `d` (so `-fu` is now caught; the old regex missed it);
    - long options and their git abbreviations: `--force`, `--force-with-lease`, `--force-if-includes`, `--mirror`, `--delete`, `--tags`, `--follow-tags`, and `--prune` (new);
    - refspecs starting with `+` or `:`, `refs/tags`, `v<digit>`;
    - any argument with `$` or a command substitution;
    - `git -c remote.*|push.*|branch.*` before the push.
  - **Kill:** a kill whose PIDs are all literal (digits or `%job`) is allowed even when the line lists processes. A non-literal kill is denied when a lister (`pgrep`, `pidof`, `ps`) sits in its own top-level segment, or anywhere on the line when it kills a `$variable`.
  - Other rules are unchanged.
- `settings.json`: added a PreToolUse entry, matcher `Write|Edit|MultiEdit|NotebookEdit`, command `.claude/hooks/guard-paths.py`, timeout 5.

## Decisions
- **Exclusion on `waves/`:** it covers any `reviews/` directory under `waves/`, not just `waves/*/reviews/`. It is stricter, and costs nothing.
- **Logging every no-agent_type write, main sessions included:** if Claude Code ever stops sending `agent_type`, subagents look like the main session, and the log is the only signal. The line holds only time, caller, tool and path.
- **Push rule tightened:** `--prune` is a ref deletion, and git accepts unique long-option abbreviations. Both are within the rule's intent, so I added them. `--all` I left alone (not in the rule today).
- **Plugin-prefixed names:** `x:tech-lead` and case variants are treated as restricted. `tech-lead-helper` is not.

## Known gaps and follow-ups
- **Bash writes are not covered.** The path guard covers only the file tools. A tech lead or reviewer can still write anywhere with `cat >`, `sed -i`, `cp` or `python -c` through Bash (guard-bash.py doesn't check write targets). Owner: platform-sre, proposed as a later card with security-reviewer.
- **The tech lead can edit its own guard's backup.** The tech lead may edit `invai-docs/team/hooks/**` and `settings.json` (it owns `team/**`), then run `sync.sh restore`. A review of any `team/hooks` diff is the control today.
- **The main session is unrestricted by design (AC2).** A tech lead started as the main session is not path-guarded.
- **Races and non-regular files:** check-then-write races (symlink swapped after the check) and hard links to directories are out of reach for a PreToolUse hook.
- **Case-sensitive filesystems:** case folding would allow e.g. `INVAI-DOCS/waves/...` as a new directory there. That's harmless (not code), and macOS is case-insensitive.
- **Sync not done**, as instructed. After both approvals: `bash invai-docs/team/sync.sh restore` copies `guard-paths.py` into `.claude/hooks/` (the flat `*.py` copy plus chmod, with `tests/` skipped) and replaces `.claude/settings.json`. The tech lead should diff `.claude/settings.json` against `invai-docs/team/settings.json` first, in case the live file has drifted.
- **Guard blocked one of my commands:** the live guard-bash.py blocked one Bash command that contained a dangerous push string inside a JSON probe payload (the same false-positive class, since the live guard still scans whole text).
