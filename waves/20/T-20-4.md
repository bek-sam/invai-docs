## Acceptance criteria
1. **Path guard.** A PreToolUse hook on Write/Edit/NotebookEdit denies a write when the acting agent is `tech-lead` and the path is outside: `invai-docs/waves/**` (excluding `waves/*/reviews/**`), `invai-docs/team/**`, `invai-docs/research/**`, `invai-docs/decisions/**`, `invai-docs/owner-inbox.md`, `CLAUDE.md` (workspace root), `.claude/agents/**`, `.claude/skills/**`, `.claude/agent-memory/tech-lead/**`, `invai-docs/.claude/agent-memory/tech-lead/**`. And when the agent is `reviewer`: only `invai-docs/waves/*/reviews/**` and `.claude/agent-memory/reviewer/**`. The denial message names the allowed paths and says "write a card for the owner".
2. **How the agent is known.** Use what Claude Code actually passes to hooks (check the installed docs or the `claude-code-guide`; record the source in your report). If the agent type isn't available for some sessions, the hook allows (fail open) for unknown agents but logs a one-line note to `invai-docs/team/state/guard-paths.log` (no content, just time, agent, path). Main sessions without an agent type are not blocked.
3. Other roles are unaffected in this card (a later card can add them).
4. **B-116.** The push rule checks flags only inside the `git push` segment; `git push origin main; echo x | tr -d y` is allowed; `git push origin :main`, `git push -d origin main`, `git push --delete`, `git push -f`, `--force-with-lease`, `+main` are still denied, including when chained (`&&`, `;`, `|`, newlines, subshells). Same segment logic for the `kill <PID>` + listing case.
5. Adversarial tests for both hooks in `invai-docs/team/hooks/tests/` (allowed and denied cases, including relative paths, `..` traversal, symlinked paths under `invai/`, absolute paths); `python3 -m pytest invai-docs/team/hooks/tests -q` passes.
