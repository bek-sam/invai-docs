## Acceptance criteria
1. **Seed with a worker running.** Given the worker is running (`pnpm dev:worker`), when `pnpm db:seed` runs on a freshly reset DB, then it completes with no unique-violation (`stock_levels` or any other) and the seeded counts match a run with the worker stopped (orders, items, transitions, stock rows). Document the cause you found.
2. **No stale jobs.** Given Valkey holds jobs from before a reset, when `pnpm db:reset` runs, then the queues the app owns (its BullMQ prefix only, in the configured Redis DB) are drained or obliterated, so a fresh worker doesn't replay jobs for rows that no longer exist. It never flushes other Redis DBs or other prefixes.
3. The seed still renders real art with imaging up; the golden-path counts and Today queues are unchanged (compare `seed-output.json` shape and the `[seed] done` counts before and after).
4. Negative stock: no `stock_levels` row with `available < 0` after the seed (B-34 part). If fixing it would change golden-path counts, stop and report instead.
