## Acceptance criteria
1. **No past peak (B-140).** Given an R1 recommendation whose act-by date is before the digest week's end (digest) or before today in the shop time zone (assistant, market list), when Market watch picks items or R1 runs, then that item is not shown or emitted. Test with a fixed clock of 2026-09-28 and a September peak: nothing says "before September".
2. **Peak under way (B-136).** Given today is inside the peak month and the item is still relevant, R1 uses the "season is on now" wording from `wave.md` (en and es), with no act-by date and no "Act now … before <past month>". R1 sets `params.niche = f.niche` (today `rules.ts:121` leaves the niche `null`), so `{{niche}}` never renders empty (PM plan review 1).
3. **Points, not relative percent (B-141).** Margin % and on-time % changes render as points with one decimal ("+6.9 pts", es "+6,9 pts"); a zero change on any metric renders "unchanged" / "sin cambio". The digest facts carry what the web needs to do the same (`formatted.en`/`formatted.es` already exist per fact; keep the wire shape, change only the values). No contract change.
4. **Mock source date (gate issue 4).** Mock market sources set `asOf` to the end of the last complete ISO week in UTC, never a future date. Email and page render "week ending Sep 27" / "semana al 27 sep".
5. **Today alert (B-137).** The overdue-label alert message shows the ship-by date in the shop's time zone and a readable form ("Ship-by was Sep 26 and no label has been bought."), never an ISO timestamp.
6. Existing digest, market and today tests stay green; the wave 19 copy test (every rendered string comes from template keys plus formatted facts) still passes. Add a test that renders a digest on 2026-09-28 in en and es and asserts none of: a past month name after "before", "Mon," in the Spanish text, "(0%" or "+26%" style relative change on margin.
