## Acceptance criteria
1. **Inventory first.** A table in `qa-report.md`: for each of `buyLabel`, `rateOrder`, `voidShipment`, `batchBuy`, `pushTracking` (Shopify and CSV channels), `syncAvailability`, `publishDraft`, `renderItemArtwork`, `submitPo`, `receivePo`: the existing test file:line that already proves "one effect on retry / crash between the call and the commit", or "none".
2. For every "none", a new acceptance test proving: a retry after a simulated crash between the outside call and the DB commit makes **exactly one** outside call (the mock provider records calls) and one DB effect; a concurrent double request makes one effect; a failure leaves a state the next retry can finish (no stuck intent).
3. **Live adapters with fetch mocked.** Shopify (orders poll with pagination and a 429 `throttleStatus`, fulfillment create), EasyPost (buy with idempotency, tracker webhook to `in_transit`/`delivered`), S&S (PO submit, read-back on retry): each runs the real adapter code with `fetch` stubbed by recorded-shape responses (seed-like, no PII, `scrub-pii-fixture`), asserting the request method, path, auth header presence (never its value) and idempotency key.
4. A test that finds a real bug is left **failing** (`it.fails` is not allowed): report it with file:line and owner, and the tech lead routes it. Never weaken or skip another test.
5. Suite time added < 60 s on `invai_test`.
