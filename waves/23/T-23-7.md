## Acceptance criteria
1. On push to `main` (and `workflow_dispatch`), each code repo runs lint, typecheck and tests (web/floor also build with `VITE_API_URL` set; imaging runs ruff + pytest).
2. An E2E job (in backend, web and floor) checks out the sibling repos at `main`. It starts Postgres with pgvector, Valkey, MinIO and imaging, migrates, seeds, and starts api/worker/web/floor. It runs the API golden path, the browser suite and the floor suite, and uploads traces on failure.
3. Every third-party action is pinned by full commit SHA (with a version comment). Each workflow sets top-level `permissions: contents: read` and nothing broader. There are no secrets and no deploy or `aws` steps, and `pull_request_target` isn't used.
4. `actionlint` is clean on every workflow. The E2E job's script is proven by running it locally. Pushing isn't possible before the gate, so the report says so: the first real CI run is observed after the tech lead's push.

## Verification
- `actionlint` output; a local run of the CI start-up script with the three suites' summary lines (on a gate slot from the tech lead).
- `grep -rn "uses:" .github/workflows` in each repo shows only SHA pins.
