## Acceptance criteria
1. `pnpm gate [repo...]` (default: repos with commits not yet on origin/main) runs typecheck, lint, the full tests (plus `pnpm build` with `VITE_API_URL` set for web/floor; imaging: ruff + pytest) for each repo. If backend/web/floor changed, it also resets, migrates and seeds the dev DB with imaging up, then runs the API golden path, browser and floor E2E.
2. Output: one line per suite: `PASS <repo> <suite> <n passed>` or `FAIL <repo> <suite>: <failing test names>`. Full logs go to a file whose path is printed at the end. No other output on stdout.
3. It refuses to start (exit non-zero, one-line reason) if an API or worker process has the test DB or test Redis open, or if a dev stack it didn't start holds :3000/:8000/:5173/:5174. It never kills processes it didn't start, and it stops everything it started, even on failure (trap).
4. On a full pass it writes a stamp (for example `invai-infra/.gate/pass.json`, gitignored) with each repo's HEAD SHA and a time.
5. `guard-bash.py` blocks a push to main of a code repo unless the stamp exists, is under 24 h old, and records that repo's current HEAD SHA. The message tells you to run `pnpm gate`. Docs-only repos (invai-docs) are exempt. All existing guards stay as they are (forced pushes, tags, deploys, aws, secrets).
6. Tests for the hook change: a stamp with a stale SHA blocks, an old stamp blocks, a matching one allows, and a forced push is still blocked.

## Verification
- Run `pnpm gate` once for real on the current tree, on a gate slot from the tech lead (it resets the dev DB), and paste the summary lines.
- Show the refusal: start one process holding the test Redis DB, run the gate, paste the refusal line, stop that process.
- Hook tests: run them and paste the output.
