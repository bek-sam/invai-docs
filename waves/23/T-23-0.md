## Acceptance criteria
1. Given `NODE_ENV=test` and `REDIS_URL=redis://localhost:6379` (DB 0, as in `.env` and CI), when the backend suite runs, then every Redis connection (`src/lib/queues.ts` `redis`, BullMQ queues and workers, `src/lib/realtime.ts` subscriber) uses a non-zero test DB (default 15, or `TEST_REDIS_URL` when set), mirroring how `TEST_DATABASE_URL` redirects Postgres.
2. Given a caller that already set an explicit non-zero DB for tests (for example `REDIS_URL=redis://localhost:6379/14`, as the agent brief tells agents today), then that still works (explicit test DB wins, or `TEST_REDIS_URL`; document which).
3. Outside `NODE_ENV=test` (development, production), `REDIS_URL` is used unchanged.
4. A test proves the redirect: under test, the parsed Redis DB index is not 0 and differs from the dev URL's DB.
5. With a dev worker running on DB 0, the full backend suite run with plain `pnpm test` (no REDIS_URL override) passes, and the dev worker's queues in DB 0 gain no test jobs (check `redis-cli -n 0 keys 'bull:*'` counts before and after, or a DB 0 key the tests would create).
