## Why the profit recompute
`profit_lines` is normally filled by the async `finance.recompute` job, fired from outbox events a
worker drains — which in the normal `pnpm db:seed` order happens *after* the script exits. Built
before that, `getProfit` saw an empty table, so margin/on-time "change" came out `null` and the web
StatCard rendered no delta at all. Found via this card's own `digest-dates.spec.ts` AC2 E2E run
(see Known gaps). Fixed by calling `recomputeProfit` (the same function the nightly job calls) before
`buildDigest`, scoped to the whole company — an upsert keyed on `(company_id, order_item_id)`, so a
second seed run is still a no-op.

- Recompute profit for the whole company (`recomputeProfit(tx, {companyId}, {})`, no scope filter)
  rather than just the two weeks the digest needs — 360 orders, chunked by 200, adds under a second;
  simpler than reasoning about exactly which weeks the digest's history lookback touches, and it's the
  correctness fix the E2E run surfaced, not a nice-to-have.

  dev-mode CSP (`vite.config.ts`) hardcodes `connect-src` to `http://localhost:3000`, so a non-default

  Not my path to fix (`invai-web`); noted below for web-engineer/architect.
