### Decisions
- Kept the simplified single-step `ref: main` sibling checkout (round 1's change) rather than restoring
  the original two-step branch-then-main fallback with `ref: ${{ github.head_ref || github.ref_name }}`:
  the ruling said "keep ref: main if it's harmless", and it is — `CLAUDE.md` states all work happens on
  `main`, so there is never a second ref to fall back from.
- Redacted the seed's secret-shaped output by piping through `sed` ahead of `tee`, so both the live job
  log and the uploaded `seed.log` are redacted identically, rather than only redacting the uploaded file
  (which would have left the token visible in the job's live console output — a smaller but real gap).
- Did not touch `invai-floor` application code for the CSP/`VITE_API_URL` fix: the mismatch only bites
  when a dev-mode `vite` server is started with `VITE_API_URL` set, which is specific to how
  `run-e2e.sh` starts floor; fixing it in the script (my owned path) is narrower than changing floor's
  config contract for every consumer of `VITE_API_URL`.

### Known gaps and follow-ups

### Blocked by other owners
- `invai-backend/src/modules/production/*` (batch build) or its outbox/worker interaction: on a fresh
  seed, the worker's backlog drain (thousands of outbox events released at once by the seed) races the
  API golden path's manual `production.batches.build` call for the same "ready, due soon" item pool,
  making which items land on the test-built sheet — and its nesting utilization — non-deterministic
  (observed 0.7951 one run, 0.8603/0.8942 the next, same deterministic seed data both times). Suggested
  owner: backend-engineer (production module) or qa-engineer (may already be tracked as a flake). Not
  something `run-e2e.sh`'s ordering can resolve without either slowing every CI run with an artificial
  wait, or the product code itself waiting for the backlog to settle before letting a manual build claim
  items — a product-code decision, not platform-sre's to make.
