## Acceptance criteria
1. The deploy workflow pins each sibling repo SHA; refuses unless each SHA's CI is green; uses the OIDC role (ARN from a repo variable, `[[OWNER]]`), no long-lived keys; builds and pushes images; runs the one-off migrate task (bootstrap, migrate, reference seed) before updating services; smoke test (`/readyz`, sign-in page, a public help page, floor handshake); automatic rollback to the previous task definitions on smoke failure.
2. Staging on manual dispatch; production only from the owner's release tag, with the `production` environment requiring the owner's approval; one deploy at a time per stage.
3. Linted with `actionlint`; a dry-run mode that prints the plan without AWS calls, exercised locally.
4. Nothing is triggered by the agent; dispatches and tags are the owner's (go-live checklist).
