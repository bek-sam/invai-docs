## Built
- `requeueBuild(companyId, date)` in `src/modules/today/jobs.ts`: looks up the existing BullMQ job
  by its stable jobId, leaves it alone if live (waiting/active/delayed/waiting-children/
  prioritized) or completed, removes it (try/catch for a concurrent-sweep race per architect
  ruling 4) if `failed`, then enqueues a fresh build. `sweepTodayActions` now calls this instead of
  `buildTodayActionsJob.enqueue` directly.
- `buildTodayActionsJob`'s handler wraps `buildTodayActions` in try/catch: logs one
  `log.warn("today actions build failed", { companyId, date, attempt, attempts, ...errorData })`
  per failed attempt, then rethrows (retry/failure behavior unchanged). No PII.

## Decisions
- Tested `requeueBuild` directly (one company/jobId at a time) rather than through
  `sweepTodayActions`, which pages over every `shop`-type company in the whole shared test
  database (`fileParallelism: false` means other today-module test files' companies, several of
  which never build a set for the exact date used, show up as "missing" — confirmed this during
  development: the broad sweep returned 5 unrelated companies on a scoped call). `requeueBuild` is
  exported for this; it's the card's own "or an equivalent within `today/**`" allowance.
- Used BullMQ's own `permanentFailure` path (a Zod-invalid `date`) to reach `failed` state
  immediately instead of waiting out 3 real attempts with 60s exponential backoff — same end
  state the card itself suggests ("force a build to fail 3 times, for example a test-only bad
  input"). The "live job" test uses the queue's actual default state, `prioritized` (the `reports`
  queue sets a default bulk priority), asserted generically via `LIVE_JOB_STATES` rather than
  hardcoding `waiting`.
- `jobs.test.ts`'s first describe obliterates the `reports` queue in `beforeAll`/`afterAll` (same
  pattern as `src/lib/queues.test.ts`): a stray job from an earlier aborted run otherwise persists
  in the shared test Redis db across invocations and gets reprocessed (observed this once during
  development; harmless but noisy).
