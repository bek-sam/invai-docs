## Decisions
- `niches.get`/`set` use `GET|PUT /market/niches/design` with `designId` as a query/body key, not `/{designId}`: `contract.test.ts` allows only a fixed list of GET path params, and the agreed input is `{designId}`. Same shape, no test change.
- `PricePosition` is a discriminated union on `available` so consumers get type narrowing for the `reason` branch; a boolean discriminant can't break an exhaustive switch.
- `MarketRecommendation` carries `action` (one fixed `MarketAction` per rule) and typed all-optional `RecommendationParams` instead of a `text` field: the spec's action copy is app-side keys with `{{params}}`, so the apps render en/es from `rule` + `params`, and the backend never stores free text except trademark-screened R4 `ideas` (≤ 2, ≤ 120 chars).
- `SignalSubject` and `RecommendationTarget` are flat nullable objects (design and/or niche), not unions, to avoid exhaustive-switch breakage later.
- `NicheKey` checks shape only (kebab-case, ≤ 64); the key list stays in the backend data file; the backend answers `UNKNOWN_NICHE`.
- `vote` stays behind `finance.read` (it records the caller's own opinion), per the plan review; PM may move it to `ai.assistant.ask` later, additively.
- Minor bump 0.5.0 -> 0.6.0 (0.x rule; additive); `FLOOR_COMPAT_BASELINE` untouched (ADR 0012).
- Cross-cutting: ADR 0015 (global cache), accepted as architecture type; security-reviewer confirms on co-review.
