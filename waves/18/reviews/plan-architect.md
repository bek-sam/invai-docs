# Wave 18 plan review: architect (design)

- Reviewer: architect (fable), 2026-09-27. Inputs: `wave.md`, T-18-1..T-18-5, `specs/market-signals.md`, read-only code checks listed at the end.
- Verdict: **approve-with-changes**. Ownership is clean (no path in two cards), the sequencing is right, and the global cache is safe as designed. Eight edits below close the gaps that would otherwise force a mid-wave grant or a contract test failure.

## Required changes
1. **`wave.md` hard fences + T-18-2/T-18-3: fix the sample-workspace test.** "Sample workspaces (`companies.demo`)" is wrong: `src/modules/tenancy/demo-flag.ts` says `companies.demo` is NOT the test (seeded Desert Bloom has `demo = true` and gets real behavior); a sample workspace is `isSampleWorkspace(companyId)` (`demoOwnerUserId` or `settings.demoRetiredAt`). Write the rule once: *mock sources are used and shown when `!env.isProd || env.allowMocks || await isSampleWorkspace(companyId)`; otherwise a mock source is no source (R2/R4 don't fire, `PricePosition.available = false, reason: no_compliant_source`, mock demand rows are skipped)*.
2. **Where the rule is enforced: T-18-3, not T-18-2.** The nightly demand refresh is global (no company), so provider selection can't apply a per-company rule. Put one predicate `mockSourcesAllowed(companyId)` in `src/modules/market/config.ts`; `computeSignals` and every read apply it, and `refreshPricing` skips storing mock comparables for shops where it is false. T-18-2 stays "key or mock" like `carriers/index.ts` and adds `readonly mock: boolean` to `DemandProvider` and `PricingProvider` so T-18-3 can decide without a call. Add this to T-18-3 AC1/AC2 and T-18-2 interfaces; ADR 0015 records it.
3. **T-18-4 owned paths: add `src/modules/ai/service.ts` + `service.test.ts` now.** The `tool_result` yield (`service.ts:1276`) emits only `name, summary`; provenance and recommendations can't reach the web without editing it, and `getConversation` (`:1349`) must return stored recommendations for T-18-5 AC4 ("survives a reload"). Persist them in `assistant_messages.toolCalls` (jsonb, no migration). Scope the ownership to the event pass-through and conversation load. Without this the grant is certain mid-wave.
4. **Contract: `market.recommendations.list` must be paginated.** `contract.test.ts` "list endpoints use cursor pagination" matches `\.list$` and requires `cursor` in and `nextCursor` out. Change the wave.md line to `list(Page.extend({designId?, ids? (≤ 20)})) -> paginated(MarketRecommendation)`; the T-18-3 service may still return an array and the router wraps it. `ids?` lets the web reload vote state for the recommendations a stored message carries; `MarketRecommendation` carries `vote: done | not_useful | null` and `votedAt`.
5. **Event shape, fixed in wave.md so T-18-4 and T-18-5 build the same thing.** `tool_result` gains optional `mock?: boolean`, `sources?: {source: SignalSource, asOf: Timestamp, mock: boolean}[]`, `recommendations?: {id: Id, rule: R1..R5, band: ConfidenceBand, mock: boolean}[]`. No new union member (a new `type` breaks exhaustive switches; the web's if-chain is safe, but keep it additive). `AssistantMessage` gains optional `recommendations?` (same item) and `mock?: boolean`. `recordRecommendationsShown` takes `{ids, shownIn, refId?}` (the `messageId` from `start`). T-18-4 AC3: "shown" means every recommendation carried in a `tool_result` of the turn, capped at 3 per tool; the web renders the vote cards from the event, not from the answer text.
6. **Permissions (wave.md line 55, T-18-1 AC2).** `niches.get` and `niches.taxonomy` reuse `catalog.read`: it is held by owner, admin, office, designer and by none of presser, packer, receiver, vendor today, which is exactly the matrix. `niches.set` needs a **new** `market.niches.manage` added to `OFFICE` and `DESIGNER` (office lacks `catalog.manage`, so no existing permission fits). Recommendations list/vote stay on `finance.read`.
7. **The `rls-coverage.test.ts` grant is two edits in the security-reviewer's file, not one line.** `PUBLIC_READ_TABLES` gains `market_series_cache` and the "app role cannot write the global catalogs" array must include it (the ADR's enforcement test). Name security-reviewer as co-reviewer of that hunk (operating-system: RLS suites are theirs) alongside backend-foundation.
8. **T-18-2 interfaces:** state `censusRetailSeries({ years })` and make Census also one of `marketDemandProviders()` (source `census`, granularity `month`) so T-18-3 treats every source through one interface; the standalone function is a convenience only. **Ownership table:** say that QA's `src/modules/market/*.acceptance.test.ts` is carved out of T-18-3's `src/modules/market/**`.

## Judgements the tech lead asked for
- **Ownership splits:** clean. Grants are one-line registrations plus `env.ts` hunks; only item 3 (ai `service.ts`) and item 7 are under-scoped. Only T-18-3 generates a migration (`AI_JOB_KINDS` is `enumText`, so T-18-4 needs none): no journal collision expected.
- **`(tx, ctx, input)` convention:** right; matches `finance/service.ts` (`ctx: Pick<TenantContext, "companyId">`) and the assistant tools' own `withTenant` wrapping. `classifyDesignNiche(companyId, …)` without `tx` is right too: it goes through the gateway, not the DB.
- **Global cache (ADR 0015, mine in T-18-1):** safe. `withSystem` is the owner connection (`db/client.ts:90`), the same path `ensureTrademarkMarks` uses, so `publicReadPolicy` + `.enableRLS()` gives the app role select-only and the nightly job writes without a policy hole. I will add: unique index `(source, query, granularity, period)`, `query` validated against `NICHES` canonical queries in the job and in a test, `mock` column, retention (weekly 7-day / Census 30-day TTL, purge periods older than 5 years), and the mock-visibility rule from item 1.
- **Sequencing:** right. Two checks that remove feared grants: module `jobs.ts` files self-register schedulers at import (`today/jobs.ts:41`, `inventory/jobs.ts:63`), so T-18-3 needs nothing in `src/worker/**`; `design.updated` already fires on create (`catalog/service.ts:196`), so T-18-3 subscribes to it and no new outbox event is needed. The seed already has Halloween designs and an Amazon channel (spec AC3).
